# M0 · 项目全景

> 目标：任何时候被问"简单介绍一下这个项目"，能在 60 秒内讲清 **动机 → 方法 → 结果 → 局限**，并且每一句都埋着可以被深挖的钩子。

---

## 1. 一句话定义

这是一个 **视觉地点识别（Visual Place Recognition, VPR）** 系统，用于 SLAM 中的 **回环检测（loop closure detection）**：给一张当前帧图像，从历史图像数据库里检索出"同一个地点"的图像。

核心难点不是"找相似图片"，而是：**同一个地点在不同时间/光照/视角下看起来完全不同，不同地点却可能长得很像**。这正是本项目要解决的问题（昼夜变化 + 横向视角变化）。

---

## 2. 三阶段 Pipeline

```text
                 ┌──────────────── 离线（建库）─────────────────┐
 database imgs ─►│ ResNet18 backbone ─► GAP ─► 512-D ─► L2 norm │─► features.pt
                 └──────────────────────────────────────────────┘
                                        │
                 ┌──────────────── 在线（查询）─────────────────┐
 query image  ──►│ 同一个 encoder ─────────────────► 512-D 向量 │
                 └──────────────────────────────────────────────┘
                                        │
                          相似度 = q · Dᵀ （L2 归一化后即 cosine）
                                        │
                                  topk ─► Top-K 候选地点
                                        │
                            （真实 SLAM 中：几何验证 → 位姿图优化）
```

三个阶段对应三个概念：

| 阶段 | 做什么 | 关键设计问题 |
|---|---|---|
| ① 特征提取 | 图像 → 定长全局向量 | 用什么 backbone？怎么池化？维度多少？ |
| ② 相似度检索 | 向量 → Top-K 候选 | 用什么度量？规模大了怎么加速？ |
| ③ 度量学习（可选） | 重塑 embedding 空间 | 什么损失？正负样本怎么采？怎么防过拟合？ |

**这三个问题就是整个项目的技术骨架**，也是面试官会依次挖的三个方向。

## 3. 代码地图

8 个模块，717 行。按 pipeline 归位：

| 文件 | 行数 | 属于哪一步 | 核心内容 |
|---|---:|---|---|
| `src/models.py` | 19 | ① | `ResNet18FeatureExtractor`：砍掉 fc，输出 L2 归一化的 512-D |
| `src/dataset.py` | 53 | ① | `ImageFolderDataset` 递归读图 + ImageNet 预处理 |
| `src/extract_features.py` | 97 | ① | 批量抽特征，存 `{features: [N,512], paths: [N]}` 到 `.pt` |
| `src/retrieve.py` | 54 | ② | `retrieve_top_k()`：一次矩阵乘法 + `topk` |
| `src/evaluate.py` | 182 | ② | Recall@K / Precision@K，支持按 split 和 index 区间切片 |
| `src/visualize.py` | 94 | ② | query + Top-K 并排可视化（定性分析用） |
| `src/triplet_dataset.py` | 107 | ③ | `TripletPlaceDataset`：(anchor, positive, negative) 采样 |

设计上有个值得一提的取舍：**特征抽取与检索解耦**，中间落地成 `.pt` 特征文件。好处是换 backbone / 换 checkpoint 后，下游的检索、评测、可视化代码一行不用改，评测可以秒级重跑。这是"工程化思维"的一个可讲点。

## 4. 数据集

**Gardens Point Walking**（QUT，室内外混合的校园步行序列）。同一条路线走三遍：

| 序列 | 角色 | 说明 |
|---|---|---|
| `day_left` | database（100 张） | 白天，走在路的**左侧** |
| `day_right` | query（100 张） | 白天，走在路的**右侧** → 只有**视角变化** |
| `night_right` | query（100 张） | 夜晚，走在路的右侧 → **视角 + 剧烈外观变化** |

三个序列**逐帧对齐**：`Image023.jpg` 在三个序列里大致是同一个地点。所以**图像编号 index 就是伪真值（pseudo ground truth）位置**，检索结果的 index 落在 query index ±3 帧内就算正确。

> 这个设计是双刃剑：省掉了 GPS/位姿真值，但也意味着"真值"只是近似对齐，且整个评测规模只有 100 张图。面试时**主动**说出这个局限，比等对方指出来强得多。见 M5 / M7。

## 5. 完整结果表（面试要背下来的数字）

**度量口径**：Recall@K = 至少一个 Top-K 结果落在 ±3 帧内的 query 比例；Precision@5 = Top-5 中正确结果的平均占比。

### 5.1 Baseline：预训练 ResNet18，零训练

| Query split | R@1 | R@5 | R@10 | P@5 |
|---|---:|---:|---:|---:|
| `day_right`（仅视角变化） | **0.960** | 1.000 | 1.000 | 0.802 |
| `night_right`（昼夜变化） | **0.510** | 0.740 | 0.870 | 0.392 |

**结论一句话**：ImageNet 预训练的 CNN 描述子对**视角变化**已经相当鲁棒（96%），但对**昼夜外观变化**几乎垮掉一半（51%）。这个对比本身就是项目的第一个发现，也是做后续度量学习的动机。

### 5.2 Triplet 微调（在**全部** `night_right` 上训练）

| Query split | R@1 | R@5 | R@10 | P@5 |
|---|---:|---:|---:|---:|
| `day_right` | 0.990 | 1.000 | 1.000 | 0.880 |
| `night_right` | **0.860** | 1.000 | 1.000 | 0.782 |

⚠️ **这组数字不能单独拿出去说**：训练和评测用了同一批 query，是 train-on-test。它只能证明"embedding 空间确实能被重塑"，**不能证明泛化**。面试官如果只听到"51% → 86%"而后来发现是这么测的，你的可信度就没了。**你必须自己先说破它**，然后拿出 5.3。

### 5.3 严格 held-out（真正该讲的结果）

只用 `night_right` 的 `Image000-069` 训练，在**完全没见过**的 `Image070-099`（30 张）上评测：

| night_right `070-099`（held-out） | R@1 | R@5 | R@10 | P@5 |
|---|---:|---:|---:|---:|
| Baseline（预训练） | 0.500 | 0.767 | 0.900 | 0.433 |
| Triplet（训于 000-069） | **0.567** | **1.000** | **1.000** | **0.493** |

同一批 30 张 query 的严格对比：

- **R@5：76.7% → 100%（+23.3 pts）**
- **R@10：90% → 100%（+10 pts）**
- R@1：50.0% → 56.7%（+6.7 pts）
- P@5：43.3% → 49.3%（+6.0 pts）

对照训练区间 `000-069`（70 张）：baseline R@1 = 0.514 → 微调后 0.914（**+40 pts**）。

**训练区间 +40 pts vs held-out 区间 +6.7 pts** —— 这个落差就是**过拟合在 top-1 精排上的量化证据**。但 held-out 的 R@5/R@10 打满 100%，说明学到的东西并非全是死记硬背：**候选召回能力是真的泛化了，精排没有。**

> 📌 **这段是整个项目最有分量的叙述**，因为它同时展示了三件事：会做严格的实验设计、能诚实地量化自己方法的局限、并且理解这个局限在下游任务里意味着什么（VPR 作为候选检索器，R@5=100% 已经够用，精排交给几何验证）。
>
> ⚠️ 注意：README 早期版本用"全序列 baseline 51%"对比"held-out 57%"，那不是同一批 query，属于口径不一致。上表是重新用同一批 30 张 query 跑出来的。**面试时用上表的数字。**

## 6. 简历该怎么写

❌ 反面写法（一眼假 / 一问就崩）：
> 基于深度学习的视觉地点识别系统，Recall@1 达 99%。

问题：99% 是 train-on-test 的数；"基于深度学习"等于没说；没有任何设计决策的痕迹。

✅ 建议写法：
> **Visual Place Recognition for SLAM Loop Closure**（PyTorch）
> - 构建 CNN 全局描述子检索 pipeline（ResNet18 → GAP → 512-D → L2 归一化 → cosine Top-K），在 Gardens Point 数据集上定量对比视角变化与昼夜变化下的检索性能，量化出昼夜外观变化使 Recall@1 从 96% 降至 51%
> - 用 triplet loss 做度量学习适配昼夜域差异，采用**时序切分的严格 held-out 评测**（训练 frame 000-069 / 测试 070-099），held-out Recall@5 从 76.7% 提升至 100%
> - 通过训练区间(+40 pts)与 held-out 区间(+6.7 pts) 的 Recall@1 增益差异定位过拟合，分析出该描述子适合作 SLAM 的**候选召回**阶段而非最终精排

三条分别对应：**工程实现能力 / 实验设计能力 / 分析与批判能力**。第三条最稀缺，也最能拉开差距。

## 7. 60 秒电梯陈述（口语稿，建议背熟）

> "这个项目做的是 SLAM 里的回环检测。机器人长时间运行会有累积漂移，需要识别出'我以前来过这里'来做位姿图优化修正。传统方案像 ORB-SLAM 用的是 DBoW2 词袋，基于手工特征，在光照剧烈变化时不太行。
>
> 我做的是学习型的全局描述子方案：用预训练 ResNet18 去掉分类头，取全局平均池化后的 512 维特征做 L2 归一化，这样点积就直接是余弦相似度，检索就是一次矩阵乘法加 topk。
>
> 我先量化了 baseline 的能力边界——在 Gardens Point 上，纯视角变化 Recall@1 有 96%，但换成夜晚就掉到 51%，说明 ImageNet 预训练的特征对几何视角鲁棒，对光照外观不鲁棒。
>
> 然后我用 triplet loss 做度量学习，把夜间图当 anchor、同位置白天图当正样本、远处白天图当负样本，把同一地点的昼夜图像在 embedding 空间里拉近。为了不自欺欺人，我按时序切了训练集和测试集，只在前 70 帧训练，后 30 帧完全 held-out。结果是 held-out 上 Recall@5 从 76.7% 提到了 100%，但 Recall@1 只从 50% 提到 57%。
>
> 这个落差本身是个有意思的发现：模型在训练区间 Recall@1 提升了 40 个点，held-out 只有 6.7 个点，说明精排那部分是过拟合的，但候选召回能力是真泛化了。而这恰好符合 VPR 在 SLAM 里的实际定位——它只负责给出 Top-K 候选，最终由几何验证来决定要不要接受这个回环。所以这个描述子在实际系统里是够用的。"

**这段话里埋了 8 个钩子**，每一个都是你已经准备好的深水区：DBoW2 对比（M8）、GAP 与池化选择（M2）、L2 归一化与余弦（M2）、检索复杂度（M4）、triplet 采样策略（M6）、时序切分（M7）、过拟合诊断（M7）、几何验证（M8）。

## 8. "这个项目你具体做了什么？"

面试官问这句，是想区分**调包侠**和**做了设计决策的人**。答题框架：不要罗列你写了哪些文件，而要讲**你在哪几个岔路口做了选择，以及为什么**。

四个可以拿出来讲的决策点：

1. **为什么用全局描述子而不是局部特征匹配？**
   VPR 的定位是从 N 张历史图里快速筛候选，全局描述子把匹配变成 O(N) 的向量内积；局部特征两两匹配是 O(N × 特征数²)，做不到实时。局部特征该用在第二阶段的几何验证上，而不是第一阶段的召回。

2. **为什么把特征抽取和检索解耦、中间落成 `.pt` 文件？**
   database 特征是离线一次性算好的，在线只需要算 query。这既符合真实系统的架构（建图阶段 vs 定位阶段），也让换 backbone / 换 checkpoint 后评测可以秒级重跑，不用重新过一遍网络。

3. **为什么选 triplet loss 而不是分类损失（比如把每个地点当一类）？**
   地点数量是开放集的，新地点随时会出现，分类头没法扩展；而且我关心的是**相对距离关系**（同一地点比不同地点更近），不是绝对类别。度量学习直接优化这个关系，学到的 embedding 对未见过的地点也可用。

4. **为什么坚持做时序 held-out 切分？**
   如果在全序列上训练再在全序列上测，Recall@1 能报到 86%，但那是自欺欺人。按时序切分才能回答"这个描述子对没走过的路段还有用吗"这个真问题。而且正是这个切分才让我发现召回泛化、精排不泛化的现象。
