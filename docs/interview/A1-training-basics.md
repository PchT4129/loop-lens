# 附录 A · PyTorch 训练基础（用本项目代码当教具）

> 穿插模块。目标是建立**直觉**：为什么要 batch、mini-batch SGD 是什么、Adam 在做什么、
> 反向传播在孪生结构里怎么走。所有例子都对应 `src/train_triplet.py` 的真实代码和真实数字。

---

## 1. 训练到底在干什么

`ResNet18FeatureExtractor` 有 **1118 万个参数**（实测 11.18 M）。所谓"模型"，本质就是这 1118 万个数字。同一张图喂进去，数字不同，输出的 512 维向量就不同。

**训练 = 找一组数字，让 loss 最小。**

### 山谷比喻

蒙上眼睛被扔在丘陵地带，要走到最低点。你看不见地形，但能感觉到**脚下的坡度**。策略：**朝最陡的下坡方向迈一步，重新感受坡度，再迈一步。**

这就是**梯度下降**，"脚下的坡度"就是**梯度**。

---

## 2. 梯度是什么

对某个参数 `w`，它的梯度回答：

> **"如果把 w 增大一点点，loss 会变大还是变小？变多少？"**

| 梯度 | 含义 | 该怎么做 |
|---|---|---|
| +5 | 增大 w 会让 loss 显著变大 | **减小** w，可以多减一点 |
| −0.01 | 增大 w 会让 loss 略微变小 | **增大** w，一点点就行 |
| 0 | 动它没影响 | 不动 |

更新规则 = 朝梯度反方向走：

```
w_new = w_old − 学习率 × 梯度
```

**学习率** = 步子迈多大。梯度给方向和陡峭程度，学习率决定你信它信到什么程度。

1118 万个参数各有梯度，拼起来是一个 1118 万维向量，指向"loss 上升最快的方向"。我们朝反方向走。

## 3. 为什么要 batch ⭐

算梯度需要数据。用多少数据算一次？三种极端：

### 3.1 选项 A：全部数据（全批量梯度下降）

**好处**：梯度**最准**，就是真实 loss 曲面的坡度。

**坏处**：
1. **内存装不下** —— ImageNet 128 万张图一次塞进显存不可能
2. **更新太慢** —— 跑完全部数据才更新**一次**，5 个 epoch 只更新 5 次
3. **容易卡住** —— 梯度太"干净"，走到鞍点（各方向坡度都接近 0）就出不来

### 3.2 选项 B：一个样本（SGD，batch=1）

**好处**：更新极频繁；梯度噪声反而能"抖"出鞍点。

**坏处**：
1. **方向很不准** —— 只反映这一个样本的诉求
2. **GPU 严重浪费** —— 几千个核心一次只处理一张图，绝大部分闲置。**batch=1 不仅不准，还慢**

### 3.3 选项 C：小批量（Mini-batch）—— 实际方案

一次 16 / 32 / 64 个，算它们 loss 的**平均**，更新一次。就是代码里的 `batch_size=16`。

### 3.4 关键直觉：梯度是一个"估计量" ⭐

> **用全部数据算的梯度是"真值"；用少量数据算的是对它的"带噪估计"。样本越多，估计越准。**

和民意调查一样：问 10 个人误差大，问 1000 个人就准。统计学告诉我们**误差按 1/√B 下降**——要把误差减半，样本数要变 4 倍。

### 3.5 实测验证 ⭐

方法：用全部 70 个三元组算"真实梯度"，再随机抽 B 个算梯度，看方向一致性（余弦，1=完全一致）。模型设 `eval()` 冻结 BN，隔离变量。

```
   batch │ 与真实梯度的方向一致性 │ 相对 batch=1 的提升
  ───────┼───────────────────────┼────────────────────
       1 │        0.163          │      1.00 ×
       2 │        0.253          │      1.55 ×
       4 │        0.353          │      2.17 ×
       8 │        0.408          │      2.50 ×
      16 │        0.620          │      3.80 ×     ← 项目使用值
      32 │        0.823          │      5.04 ×
      64 │        0.984          │      6.03 ×
```

- **batch=1 余弦仅 0.163** —— 单样本梯度和真实方向几乎只是"沾点边"，等于拿着极不靠谱的指南针走路
- **batch=16 到 0.620** —— 方向明显靠谱
- **batch=64 到 0.984** —— 总共才 70 个样本，64 个已近全部，符合预期

**验证 1/√B 定律**：

| batch | 理论（√B 倍） | 实测 |
|---:|---:|---:|
| 4 | 2.00 × | **2.17 ×** |
| 16 | 4.00 × | **3.80 ×** |

吻合良好。

### 3.6 这张表的三个结论

**① batch 的作用是"降噪"**，通过平均多个样本的梯度抵消随机噪声。

**② 收益递减。** 1→4 质量涨 2.17 倍，代价 4 倍算力；16→64 只涨 1.6 倍，代价又是 4 倍。**所以无限增大 batch 不划算。**

**③ 噪声不全是坏事。** 适度梯度噪声有**正则化效果**——让模型不容易停在尖锐局部极小点（噪声一抖就滑走），倾向于停在**平坦极小点**，而平坦极小点通常**泛化更好**。

所以 batch size 是三者权衡：

```
        梯度质量（越大越好）
             ／      ＼
    硬件效率           正则化噪声
   （越大越好）        （适度最好）
```

16 / 32 / 64 这些常见值就是这个权衡的经验落点。

## 4. 本项目实际更新了几次参数？

```
训练集：night_right Image000-069 → 70 个 anchor
batch_size = 16  →  ceil(70/16) = 5 个 batch/epoch
epochs = 5

总更新次数 = 5 × 5 = 25 次
```

> ⚠️ **整个训练，1118 万个参数总共只被更新了 25 次。**（全序列训练版本是 7×5 = 35 次）

对比：从头训练 ImageNet 通常是几十万次更新。

**两个后果**（M7 伏笔）：

1. **模型不可能被"训坏"** —— 25 步走不远，预训练权重的大结构基本保留。这解释了为什么微调后 `day_right` 不降反升（96%→99%）
2. **但足以过拟合** —— 训练数据只有 70 个 anchor，每步都在拟合同一批数据。25 步 × 70 样本的信息量，远撑不起 1118 万参数

## 5. Epoch / Batch / Iteration

| 术语 | 含义 | 本项目 |
|---|---|---|
| **Epoch（轮）** | 完整过一遍训练集 | 5 |
| **Batch（批）** | 一次前向+更新用的样本数 | 16 |
| **Iteration / Step（步）** | **一次参数更新** | 5 步/epoch，共 25 步 |

```
总步数 = epochs × ceil(样本数 / batch_size)
```

> 面试里"训练了多少 step"问的是**更新次数**。大模型训练一般只说 step，因为数据是流式的，没有"过完一遍"的概念。

## 6. 优化器：从 SGD 到 Adam ⭐

```python
optimizer = torch.optim.Adam(model.parameters(), lr=1e-4)
```

Adam 是一条演进链的终点，每一步都在解决上一步的具体问题。

### 6.1 起点：朴素 SGD

```
w ← w − lr × g
```

**问题一：所有参数共用一个学习率。** 不同层梯度尺度可能差几个数量级——深层 0.01，浅层 0.00001。用同一个 lr：浅层几乎不动；调大 lr 让浅层动起来，深层就炸了。

**问题二：峡谷地形震荡。** 又长又窄的山谷，横向陡、纵向缓。梯度主要指横向 → 在两侧谷壁来回横跳，真正要走的纵向进展极慢。

### 6.2 改进一：动量（Momentum）

```
v ← β·v + g          （β 通常 0.9）
w ← w − lr × v
```

**比喻**：从"每步重新判断方向"变成**小球滚下山**——有惯性，不因局部坡度变化就急转弯。

治好上面两个病：
- **峡谷震荡**：左右横跳的梯度方向相反，累加后**互相抵消**；纵向梯度方向一致，累加后**越来越大** → 横向被抑制、纵向被加速
- **平坦区**：靠惯性冲过去，不会停滞

### 6.3 改进二：自适应学习率（AdaGrad → RMSProp）

思路：**给每个参数配自己的学习率**，依据是这个参数**历史上梯度有多大**：

- 梯度一直很大 → 很"活跃" → 步子迈小点，别冲过头
- 梯度一直很小 → 很"迟钝" → 步子相对迈大点

**AdaGrad** 累加历史梯度平方，开根号去除学习率。致命问题：**累加值只增不减，学习率最终趋近 0，训练卡死**。

**RMSProp** 把"累加"换成"**指数移动平均**"（只记最近一段），学习率不再归零。

### 6.4 Adam = Momentum + RMSProp

```
m ← β₁·m + (1−β₁)·g          ← 一阶矩：梯度的平均（动量，管方向）
v ← β₂·v + (1−β₂)·g²         ← 二阶矩：梯度平方的平均（管步长）

w ← w − lr × m̂ / (√v̂ + ε)
```

**一句话直觉**：

> **分子 `m` 是"平滑过的方向"（惯性）；分母 `√v` 是"这个参数最近有多活跃"。**
> **活跃的参数（梯度大）被除以大数，步子自动变小；迟钝的参数被除以小数，步子相对变大。**
> **结果：每个参数根据自己的梯度历史，自动获得合适的步长。**

默认 `β₁=0.9`（m ≈ 最近 10 步的平均）、`β₂=0.999`（v ≈ 最近 1000 步的平均）。

**帽子 `m̂`、`v̂` 是偏差修正（bias correction）**：`m`、`v` 都初始化为 0，第一步 `m = 0.1×g` 严重偏小，除以 `(1−β₁ᵗ)` 校正。训练几十步后可忽略。

### 6.5 为什么本项目用 Adam

微调场景下不同层梯度尺度差异大，Adam 的自适应机制自动处理，省去大量调参。**开箱即用、不太挑超参**，这是它成为默认选择的原因。

> ⚠️ **值钱的补丁**：
>
> **Adam 收敛快，但泛化常不如 SGD + Momentum。** CV 领域追求最终精度的训练大量使用 SGD+Momentum + 学习率调度。度量学习/检索领域也常用 SGD 或 **AdamW**。
>
> **AdamW** 修正了 Adam 的一个真实缺陷：Adam 把 weight decay 混进梯度里，会被自适应分母 `√v` 缩放，导致正则化强度在不同参数上失控。AdamW 把 weight decay 从梯度中**解耦**，直接作用于参数。**现在 AdamW 基本是新项目的默认选择。**

## 7. 学习率为什么是 1e-4

| 场景 | 典型学习率 |
|---|---|
| 从头训练（SGD） | 0.01 ~ 0.1 |
| 从头训练（Adam） | 1e-3 |
| **微调预训练模型（Adam）** | **1e-5 ~ 1e-4** |

**为什么微调要小？** 预训练权重已在**很好的位置**（ImageNet 学到的通用视觉特征）。大学习率 = 大步子，几步就能破坏这些结构——**灾难性遗忘（catastrophic forgetting）**。

小学习率的意思是："在原有好位置附近**微调**，别走太远。"

> ⚠️ 代码里**没有学习率调度**，全程 1e-4。标准做法是加 **warmup**（前几步用更小 lr 热身，避免梯度不稳时大步走坏）+ **cosine decay**（后期减小，精细收敛）。M7 的改进项之一。

## 8. 反向传播在三个分支里怎么走

```python
anchor_features   = model(anchor)      # 第 1 次 forward
positive_features = model(positive)    # 第 2 次
negative_features = model(negative)    # 第 3 次
loss = criterion(anchor_features, positive_features, negative_features)
loss.backward()
```

**关键：三次 forward 用的是同一个模型、同一套参数。**

```
                    loss
                  ／  |  ＼
                 ／   |    ＼
        a_feat      p_feat    n_feat
           |          |          |
        [model]    [model]    [model]      ← 同一套参数！
           |          |          |
        anchor    positive   negative
```

梯度从 loss 出发，**沿三条路径分别回流**，最终都到达**同一批参数**。

某个卷积核 `W` 收到的梯度 = **三条路径贡献之和**。

数学上完全正确：`W` 参与了三次计算，`loss` 对它的总导数就是三个偏导之和（链式法则 + 多路径求和）。

**在 PyTorch 里这是"自动"发生的**——因为 `param.grad` 是**累加**的（`+=`），三条路径回流时自然加到一起。

> 📌 **串联两个知识点**：M6 讲"为什么必须 `zero_grad()`"时说 PyTorch 梯度是累加的。
> **这个累加特性不是防呆设计，它是多分支网络（孪生结构、多任务、多损失）能正常工作的基础机制。** "必须手动清零"才是副作用。

**直觉版**：一个卷积核同时影响了 anchor、positive、negative 三个特征，所以要为这三份影响同时负责，收到三份"责备"。

## 9. 一次完整迭代，逐行串起来

```python
for batch in loader:                              # ① 取一批 16 个三元组
    anchor   = batch["anchor"].to(device)         # ② 搬到 GPU
    positive = batch["positive"].to(device)
    negative = batch["negative"].to(device)

    anchor_features   = model(anchor)             # ③ 前向：算出 16×512 特征
    positive_features = model(positive)           #    同时构建计算图
    negative_features = model(negative)           #    （记录每步运算供反向用）

    loss = criterion(a_f, p_f, n_f)               # ④ 这 16 个三元组的平均 loss

    optimizer.zero_grad()                         # ⑤ 清空上一步梯度残留
    loss.backward()                               # ⑥ 反向：算出 1118 万个梯度
                                                  #    三分支梯度在共享参数处累加
    optimizer.step()                              # ⑦ Adam 更新参数，每个参数按
                                                  #    自己的 m 和 v 决定步长
```

**跑完一遍 = 一个 iteration = 参数更新一次。** 本项目共 **25 次**。

## 10. 常见困惑

**Q：loss 在降，是不是训练就有效？**

**不一定。** loss 降低只说明"三元组的 margin 约束被满足得更好"，不等于"检索指标变好"。尤其当大量三元组已零梯度、loss 主要靠简单样本拉低时，两者会脱节。

> **正确做法：每个 epoch 结束在验证集上跑真实的 Recall@K。本项目代码没有这一步。**（M7）

**Q：改了 batch size，学习率要不要跟着改？**

要。经验法则叫**线性缩放规则**：batch size 翻倍，学习率也翻倍。直觉是 batch 大了梯度更准，可以更放心迈大步。极大 batch 时规则失效，需配 warmup。

**Q：loss 曲线为什么震荡？**

每个 batch 随机抽取、难度不同。§3.5 显示 batch=16 时梯度方向余弦只有 0.62——**每步的方向本来就有相当大随机性**。看趋势不看单点。

**Q：`model.train()` 起什么作用？**

切换 BatchNorm 和 Dropout 行为（M3 详述）。训练时 BN 用当前 batch 统计量并更新 running stats。

> ⚠️ **这正是本项目隐患的来源**：`train()` + 三次 forward + 每次 forward 的数据域完全不同。M7 详谈。

## 11. 面试怎么答

### Q1：为什么要用 mini-batch，而不是全量或单样本？

> 核心是把梯度理解成一个估计量——全量算的是真值，单样本算的是高方差估计。全量的问题是内存装不下、更新太慢、而且梯度太干净容易卡在鞍点；单样本的问题是方向很不准，而且 GPU 几千个核心大部分闲置，不仅不准还慢。
>
> mini-batch 是折中。我在自己项目上实测过：batch=1 时梯度方向和全量真实梯度的余弦只有 0.163，batch=16 是 0.620，batch=64 是 0.984。而且误差是按 1/√B 下降的，实测 batch=4 时质量是 batch=1 的 2.17 倍，理论预测 2 倍，吻合得很好。这也说明收益递减——要质量翻倍得付 4 倍算力，所以 batch 不是越大越好。
>
> 还有一点，梯度噪声不全是坏事，适度噪声有正则化效果，让模型倾向停在平坦极小点而不是尖锐极小点，泛化更好。

### Q2：Adam 相比 SGD 好在哪？

> Adam 是 Momentum 和 RMSProp 的结合。一阶矩 m 是梯度的滑动平均，起动量作用管方向，能抑制峡谷地形里的震荡、冲过平坦区；二阶矩 v 是梯度平方的滑动平均，用来做自适应步长——梯度一直很大的参数被除以一个大数，步子自动变小，迟钝的参数步子相对变大。所以每个参数都能拿到适合自己的学习率，这在不同层梯度尺度差好几个数量级的微调场景里特别有用，基本不用怎么调参。
>
> 不过 Adam 收敛快但泛化常不如 SGD+Momentum，CV 里追求最终精度的训练还是大量用 SGD 加学习率调度。另外 Adam 有个真实缺陷：weight decay 被混进梯度里，会被自适应分母缩放，导致正则化强度失控，AdamW 把它解耦出来了，现在新项目基本默认 AdamW。

### Q3：为什么微调用 1e-4 而不是 1e-3？

> 预训练权重已经在一个很好的位置了，大学习率意味着大步子，几步就能破坏 ImageNet 上学到的通用特征，这叫灾难性遗忘。微调的语义就是"在原有好位置附近小幅调整"，所以典型区间是 1e-5 到 1e-4。不过我这里没加学习率调度，标准做法应该配 warmup 加 cosine decay。

### Q4：孪生结构里梯度是怎么回传的？

> 三次 forward 用的是同一个模型同一套参数，所以 loss 反向传播时梯度会沿三条路径分别回流，最终都到达同一批参数，在那里求和。数学上这就是链式法则加多路径求和——一个卷积核参与了三次计算，就要为三份影响同时负责。
>
> 在 PyTorch 里这是自动的，因为 `param.grad` 是累加的。顺带说，这个累加特性不是防呆设计，它正是多分支结构能工作的基础机制，"必须手动 zero_grad" 反而是它的副作用。
