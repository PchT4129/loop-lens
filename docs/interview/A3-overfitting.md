# 附录 C · 过拟合、泛化与正则化

> 穿插模块，M7 的地基。所有概念都用本项目的真实数字落地。

---

## 1. 训练不是目的

你训练模型**不是为了让它在训练数据上表现好**——训练数据的答案你本来就知道。

> **你要的是模型在从没见过的数据上也能表现好。这个能力叫泛化（generalization），它是机器学习唯一的目标。**

### 1.1 一个极端例子

做一个"模型"，把 70 张训练图和正确答案**背下来**存成查找表：

- 训练集：**100% 正确，loss = 0**
- 第 71 张没见过的图：**完全不知道输出什么**

训练指标无懈可击，但一文不值。**因为它在记忆，不是在学习。**

真实神经网络会做同一件事，只是没这么明显——用 1118 万参数"记住"训练数据的特定模式，而非学到可迁移的规律。**这就是过拟合。**

---

## 2. 过拟合的本质

> **模型的"自由度"远大于数据能提供的"约束"。**

数学比方：

- **70 个方程**（70 个训练样本）
- **1118 万个未知数**（1118 万个参数）

无穷多组解。其中有一些是"真正理解了规律"的好解，但**绝大多数只是恰好让这 70 个方程成立**，换 30 个新方程就全崩。

优化器不知道哪个是好解，它只知道让 loss 变小，随便找到一个满足这 70 个方程的解就停。

### 2.1 本项目的比例

```
可训练参数：1118 万
训练样本：  70 个 anchor
比例：      约 16 万 : 1
```

**每个训练样本要"负责"约束 16 万个参数。** 这个比例下不过拟合才奇怪。

---

## 3. 怎么诊断过拟合 ⭐

### 3.1 唯一可靠的方法

> **比较模型在"见过的数据"和"没见过的数据"上的表现。两者的差距就是过拟合的量。**

这个差距叫 **泛化间隙（generalization gap）**。

### 3.2 本项目实测

同一个 checkpoint（只在 `night_right` 的 `Image000-069` 上训练），两个区间评测：

| Recall@1 | 训练区间 000-069<br>（模型见过，70 query） | held-out 070-099<br>（模型没见过，30 query） | **间隙** |
|---|---:|---:|---:|
| **训练前**（baseline） | 0.5143 | 0.5000 | **1.4 点** |
| **训练后**（triplet） | **0.9143** | **0.5667** | **34.8 点** |
| 提升 | **+40.0 点** | **+6.7 点** | |

**逐行读：**

**第一行（训练前）**：baseline 对两个区间**都没见过**，所以表现几乎一样——**间隙仅 1.4 点，噪声级别**。这一行的作用是**基准对照**：证明两个区间本身难度相当，没有一个天生更简单。

**第二行（训练后）**：训练区间飙到 91.4%，held-out 只有 56.7%，**间隙 34.8 点**。

> 📌 **关键推理链**：
>
> **训练前间隙 1.4 点 → 训练后间隙 34.8 点。**
>
> **这 33 点的间隙完全是训练过程"造"出来的。** 模型确实学到了东西，但学到的东西里绝大部分只对它见过的那 70 帧有效。
>
> 这不是推测，是**定义式的证据**。面试时能讲出这个对照，比说"我觉得有点过拟合"强一个量级。

### 3.3 ⚠️ 错误的诊断方式

**只看训练 loss 是没用的。** 训练 loss 下降可能意味着"学得好"，也可能意味着"背得好"，**它无法区分这两者**。

> **要诊断过拟合，必须有一份模型没见过的数据。没有它，你是瞎的。**

## 4. train / validation / test 的分工

| 数据集 | 用来做什么 | 模型"见"过吗 |
|---|---|---|
| **训练集 train** | **更新参数**（梯度下降） | 直接见过 |
| **验证集 validation** | **调超参**、早停、选 checkpoint | **间接**见过 |
| **测试集 test** | **最终评估一次** | 从未见过 |

### 4.1 为什么 val 和 test 必须分开

假设只有 train 和 test。训练完在 test 上测，效果不好 → 把 lr 从 1e-4 改成 1e-5 → 再测 → 再改 margin → 再测……

> **你已经在用 test 做决策了。**
>
> 模型参数没有直接在 test 上更新，但**你这个人**看着 test 结果在调超参，信息通过你泄漏进了模型。
>
> 结果：test 成绩**乐观偏差**，不再代表真实的未见数据表现。

标准流程：**在 validation 上调到满意，最后才在 test 上跑一次。**

### 4.2 本项目的情况

**做对的**：切了严格的 held-out 区间，训练时确实没用过。

**缺的**：**没有验证集**。所以没法早停、没法选 checkpoint、超参基本是拍的。

> 诚实的面试说法：「我切了训练和 held-out，但没有单独的验证集，所以超参基本按经验取默认值、没调过——好处是至少没通过调参污染 held-out，坏处是没法做早停和模型选择。数据只有 100 帧，再切三份每份都太小，如果重做我会用 k 折交叉验证。」

## 5. 时序数据的划分陷阱 ⭐

### 5.1 随机划分会怎样

把 `Image000`~`Image099` **随机打乱**，80% 训练 20% 测试。看起来标准，**但这是错的**。

因为 `Image049` 和 `Image050` 是**相邻帧**——同一条路相隔一两步拍的，画面几乎一样。

```
随机划分后：
  训练集里有 Image049  ←─┐
                         ├─ 这两张几乎是同一张图！
  测试集里有 Image050  ←─┘
```

模型训练时见过 `Image049`，测试遇到 `Image050` 当然表现好——**但这不是泛化，是变相作弊**。这叫**时序泄漏 / 邻近泄漏（temporal leakage）**。

> 📌 **通用原则**：**数据点之间存在相关性（时间、空间、来源）时，随机划分会造成泄漏。** 必须按相关性的分组切：
> - 时间序列 → 按时间切
> - 同一病人的多张 CT → 按病人切
> - 同一用户的多条记录 → 按用户切

### 5.2 本项目做对了

```
--min-index 0  --max-index 69     # 训练
--min-index 70 --max-index 99     # 测试
```

**按帧号顺序切，不打乱**，物理上是路线上两段不同区域。正确做法。

> 面试要主动讲：「我按时序切分而不是随机切分，因为相邻帧几乎是同一张图，随机切会造成邻近泄漏，测出来的成绩是虚高的。」

### 5.3 但边界处还有残留泄漏

```
... Image067  Image068  Image069 │ Image070  Image071 ...
       └────── 训练 ──────┘        └────── 测试 ──────┘
                      ↑          ↑
                   相邻帧，几乎一样
```

标准做法是中间**留一段 gap**（训练 0-64、测试 70-99，丢掉 65-69），叫 **purged split**（金融时序里是标配）。

> 影响不大（30 帧里可能影响 2-3 帧），但**你看得见它**这件事本身有价值。

## 6. 正则化武器库

> **定义：任何以"牺牲训练集表现"为代价、换取"泛化能力提升"的手段。**

按作用机制分五类：

### 6.1 A 类：直接限制模型容量

- **用更小的网络**（ResNet18 → ResNet10）
- **冻结部分层**：只训练 `layer4`，前面不动 → 可训练参数大幅下降

> **这一条对本项目最对症**——预训练的前几层学的是边缘、纹理等通用特征，本就不需要为昼夜任务改动。M7 展开。

### 6.2 B 类：惩罚"复杂"的解

- **L2 正则 / weight decay**：loss 里加 `λ·Σw²`，权重倾向小值

  **直觉**：权重小 → 函数更平滑 → 输入变化一点输出不会剧烈跳变 → 不易拟合噪声细节

- **L1 正则**：加 `λ·Σ|w|`，把很多权重压到**恰好为 0**（稀疏化），相当于自动特征选择

> ⚠️ **本项目 `torch.optim.Adam` 的 `weight_decay` 默认是 0**，即**完全没有 L2 正则**。要加应该用 **AdamW**（A1 §6.5）。

### 6.3 C 类：注入噪声

- **Dropout**：训练时随机置零一部分神经元。**直觉**：模型不能依赖任何单个神经元，必须分散存储信息 → 更鲁棒。（ResNet 结构通常不用，靠 BN 和增强）

- **数据增强**：随机裁剪、翻转、颜色抖动等

  > ⚠️ **本项目完全没有数据增强**（`get_default_transform` 只有 resize + 归一化）。而对昼夜任务，**ColorJitter、亮度/对比度扰动简直是量身定做**——它们模拟的正是光照变化。**这是最容易实现、收益最明确的改进项之一。**

- **BatchNorm 的副作用**：batch 统计量带随机性，有轻微正则效果

- **梯度噪声**：A1 讲过，小 batch 的噪声帮助逃离尖锐极小点

### 6.4 D 类：提前停止（Early Stopping）

验证集指标开始变差时停下。

**直觉**：训练早期先学通用规律，后期才开始记忆细节。在"开始记忆"之前叫停。本质上也是在限制**有效容量**。

> ⚠️ 本项目**没有早停**（没有验证集），固定跑 5 个 epoch。

### 6.5 E 类：增加信息量

- **收集更多数据**：最根本
- **迁移学习 / 预训练**：**借用别的数据集的信息**

> 📌 **本项目已经在用 E 类，而且这是它最重要的一道保险。**
>
> ImageNet 预训练权重携带了 128 万张图的信息，你只是在此基础上微调 25 步。若从随机初始化开始，70 个样本连收敛都做不到。
>
> **能指出"预训练本身就是最强的正则化"，是很有水平的观察。**

## 7. 反直觉问题："只更新 25 次怎么可能过拟合？"

**第一层**：过拟合和步数关系不大，和"**在同一批数据上走了多远**"有关。25 步全部踩在同一批 70 个样本上，且 Adam 的自适应会给每个参数配合适步长，实际移动距离不小。

**第二层**：真正决定性的是**自由度 vs 约束**的比例。1118 万参数对 70 样本，哪怕只走 25 步，优化器也有足够自由度找到一个"专门讨好这 70 个样本"的方向。

**但反过来，25 步这个小数字确实提供了保护**——解释了为什么模型没被训坏：

```
day_right（完全没参与训练）：  96% → 99%   ← 不降反升
```

若步数再多几个数量级，预训练的通用视觉特征会被逐渐破坏，`day_right` 也会开始掉。

> **"只训了 5 个 epoch"在这里同时扮演两个角色：既是过拟合的不足（约束太少），又是一种隐式的早停（走得不远）。**

## 8. 本项目完整诊断表

| 正则化手段 | 现状 | 说明 |
|---|---|---|
| **预训练权重** | ✅ **有** | 最强的一道保险，借了 ImageNet 128 万张图的信息 |
| **小步数（隐式早停）** | ✅ 有（意外获得） | 只更新 25 次，限制了走偏距离 |
| **小 batch 梯度噪声** | ✅ 有（副产品） | batch=16 |
| **数据增强** | ❌ **无** | 只有 resize + 归一化。**昼夜任务最该加 ColorJitter** |
| **weight decay / L2** | ❌ **无** | Adam 默认 `weight_decay=0` |
| **冻结部分层** | ❌ 无 | 1118 万参数全部可训练 |
| **Dropout** | ❌ 无 | ResNet 一般不用，可接受 |
| **验证集 + 早停** | ❌ **无** | 固定 5 epoch，无法模型选择 |
| **更多数据** | ❌ 无 | 70 个 anchor 是硬约束 |

> **面试可直接口述前三条缺失项**：没有数据增强、没有 weight decay、没有验证集和早停。**能一口气列出并说明每条为什么对症，比含糊说"有点过拟合"有力得多。**

## 9. 现代补充：双下降（加分点）

上面是**经典**偏差-方差观点：模型越大越容易过拟合，验证误差呈 U 型。

深度学习时代出现了打破这个图景的现象——**双下降（Double Descent）**：

```
验证误差
   │＼
   │  ＼      ／＼
   │    ＼_／    ＼＿＿＿＿＿
   │   经典U型     ↑ 继续增大模型，误差【又开始下降】
   └────────────────────────► 模型容量
              ↑
         插值阈值（刚好能完美拟合训练集）
```

在模型容量刚好能完美拟合训练数据的那个点附近误差最差；**继续增大模型，泛化反而又变好**。这就是为什么现在的大模型（参数量远超数据量）依然泛化得好。

> 被追问"大模型参数比数据还多为什么不过拟合"，能提到双下降和**隐式正则化**（SGD 本身倾向找平坦、低复杂度的解），说明知识不止停留在教科书。

## 10. 面试怎么答

### Q1：什么是过拟合？怎么判断？

> 过拟合是模型的自由度远大于数据能提供的约束，导致它记住了训练数据的特定模式而不是学到可迁移的规律。判断的唯一可靠方法是比较模型在见过的数据和没见过的数据上的表现差距。
>
> 我在自己项目上做过这个对照：训练前 baseline 在训练区间和 held-out 区间的 Recall@1 分别是 51.4% 和 50.0%，差距只有 1.4 个点，说明两个区间难度本来相当。训练之后变成 91.4% 和 56.7%，差距 34.8 个点。**也就是说这 33 个点的泛化间隙完全是训练过程造出来的**，这就是过拟合的直接证据。只看训练 loss 是看不出来的，loss 下降无法区分"学会了"和"背下来了"。

### Q2 ⭐：你的数据是怎么划分的？为什么这么划分？

> 按时序切，前 70 帧训练、后 30 帧 held-out，不随机打乱。因为这是同一条路线连续采集的序列，相邻帧几乎是同一张图，如果随机划分，训练集里的 Image049 和测试集里的 Image050 实质是同一个地点，模型等于提前见过答案，这叫邻近泄漏，测出来的成绩是虚高的。
>
> 这个原则更一般的说法是：当数据点之间存在时间、空间或来源上的相关性时，随机划分就会泄漏，必须按相关性分组切——时序按时间切，医学影像按病人切，用户数据按用户切。
>
> 我这个切法还能更严格：Image069 和 Image070 仍然相邻，标准做法是中间留一段 gap 丢掉，叫 purged split。

### Q3：你有验证集吗？

> 没有，只有训练和 held-out 测试。所以我的超参基本是按经验取的默认值，没有调过。好处是至少没有通过反复调参把 held-out 污染掉——如果在测试集上反复调参，虽然模型参数没直接在上面更新，但信息通过我这个人泄漏进去了，测试成绩会有乐观偏差。坏处是没法做早停和模型选择，只能用最后一个 epoch 的 checkpoint。数据只有 100 帧，再切三份每份都太小，重做的话我会用 k 折交叉验证。

### Q4 ⭐：你的模型为什么会过拟合？能怎么改？

> 根本原因是自由度和约束的比例：1118 万个可训练参数对 70 个训练样本，大概 16 万比 1。
>
> 正则化手段我基本都没用。缺的按优先级排：**第一是数据增强**，我只做了 resize 和归一化，而对昼夜这个任务，ColorJitter、亮度对比度扰动几乎是量身定做的，模拟的正是光照变化；**第二是 weight decay**，Adam 默认是 0，等于完全没有 L2 正则，要加的话应该用 AdamW；**第三是验证集加早停**，我固定跑 5 个 epoch，没有依据。另外还可以冻结前面几层只训 layer4，因为浅层学的是边缘纹理这类通用特征，本来就不需要为昼夜任务改动。
>
> 不过要说明，项目里有两道天然的保护：一是 ImageNet 预训练权重，它携带了 128 万张图的信息，**预训练本身就是最强的正则化**；二是我只更新了 25 次参数，相当于一种隐式早停，这解释了为什么完全没参与训练的 day_right 不降反升，从 96% 到了 99%。

### Q5：只更新了 25 次参数，怎么还会过拟合？

> 过拟合和步数关系不大，关键是在同一批数据上走了多远。这 25 步全部踩在同一批 70 个样本上，而且 Adam 会给每个参数配自适应步长，实际移动距离不小。更根本的是自由度和约束的比例——1118 万参数对 70 样本，哪怕只走 25 步，优化器也有足够的自由度找到一个专门讨好这 70 个样本的方向。
>
> 反过来说 25 步也确实提供了保护，它是一种隐式早停。如果步数再多几个数量级，预训练学到的通用特征会被破坏，连 day_right 都会开始掉。

### Q6：大模型参数量远超数据量，为什么不过拟合？

> 这打破了经典的偏差-方差 U 型曲线，现在的解释之一是双下降现象：在模型容量刚好能完美拟合训练集的那个插值阈值附近误差最差，但继续增大模型，泛化反而又变好。另一个角度是隐式正则化——SGD 这类优化器本身就倾向于找平坦、低复杂度的解，即使模型有能力记住全部数据，优化过程也不一定会走到那种解上。
