## 1. 先说清楚，训练的目标是什么

M2 里实测过一个**判别间隙**（同一地点对的平均相似度 − 全体图像对的平均相似度）：

| | 同地点相似度 | 全体平均 | 间隙 |
|---|---:|---:|---:|
| 白天 query | 0.882 | 0.725 | **0.157** |
| 夜间 query | 0.744 | 0.663 | **0.081** |

夜间间隙只有白天一半 —— **正确答案和干扰项的分数太接近，排序稍微一抖就错**。

所以训练目标不是模糊的"让模型更强"，而是非常具体的一件事：

> **把同一地点的昼夜图像在向量空间里拉近，把不同地点的推远——把那个 0.081 撑开。**

后面每一步都在服务这个目标。

---

## 2. 什么是度量学习

| | 分类学习 | 度量学习 |
|---|---|---|
| 学什么 | 图像 → 哪个类别 | 图像 → 一个向量 |
| 关心什么 | 类别对不对 | **向量之间的距离关系**对不对 |
| 输出 | "这是猫" | 512 维向量 |
| 训练信号 | 真实标签 | "这两个该近 / 这两个该远" |

**度量学习不关心"这是哪里"，只关心"哪两张该挨得近"。**

### 2.1 为什么 VPR 用度量学习而不是分类？

**① 地点是开放集**。机器人会去新地方。分类器输出层固定 100 类，来了第 101 个地点就得重训输出层。度量学习学的是"怎么把图像变成向量"这个能力，**新地点直接抽特征入库，模型完全不动**。

**② 问题本质是关系判断**。"这两张是不是同一地点"本来就不是分类，是比较。度量学习直接优化这个关系。

> ⚠️ **要留的补丁**：**CosPlace（CVPR 2022）恰恰把 VPR 当分类做**——按 GPS + 朝向分组当类别，用大间隔 softmax（CosFace）训练，效果很好，动机就是绕开三元组挖掘的巨大开销。所以准确说法是"在我这个规模和设定下度量学习更自然"，不是"分类不行"。

## 3. 三元组是什么

| 角色 | 是什么 | 项目里的例子 |
|---|---|---|
| **anchor** 锚点 | 基准那张 | `query/night_right/Image050.jpg`（**夜里**） |
| **positive** 正样本 | 同一地点 | `database/day_left/Image050.jpg`（**白天**） |
| **negative** 负样本 | 不同地点 | `database/day_left/Image005.jpg` |

一句话说清训练要求：**让 anchor 离 positive 比离 negative 更近。**

### 3.1 这个设计的巧妙之处 ⭐

anchor 是**夜里**的，positive 是**白天**的。所以"拉近 anchor 和 positive"这个动作本身，就等于**在教模型忽略昼夜差异**。

> 📌 **这是整个训练设计的核心**：不是随便找两张相似的图拉近，而是**刻意跨越昼夜这个域**去拉近。**三元组的构造方式，直接编码了你想让模型学会的不变性。**
>
> 面试时能讲出这一层，说明你理解了设计意图，而不只是套了个 triplet loss。

## 4. Triplet Loss 公式逐项拆解

```
L = max( 0,  d(a,p) − d(a,n) + margin )
```

| 项 | 希望它 | 在 loss 里的符号 | 优化器会怎么做 |
|---|---|---|---|
| `d(a,p)` | 小（同地点该近） | **正** | 越大 loss 越大 → 压小它 ✓ |
| `− d(a,n)` | 大（不同地点该远） | **负** | 越大 loss 越小 → 撑大它 ✓ |

前两项合起来 `d(a,p) − d(a,n)`：希望是**负的**，即正样本更近。

**`+ margin`**：如果没有它，"正样本只比负样本近一丁点"也算达标，模型会停在非常勉强的状态。加上 margin 等于说：**不满足于"稍微近一点"，要求近至少 margin 这么多。**

**`max(0, ...)`**：已经做到了（括号内为负）→ loss 归零。

> 📌 **triplet loss 最重要的性质：做到了就不再推。**
>
> 对比交叉熵——分类模型已经 99% 确信是猫时，交叉熵仍会继续推向 100%，永远有梯度。triplet loss 满足 margin 后彻底闭嘴，梯度为 0。
>
> **这是双刃剑**：好处是把注意力留给还没学会的样本；坏处是如果大部分三元组太容易，模型很快就没事可干（见 §9）。

## 5. margin = 0.2 到底是多大 ⭐

`p=2` 是欧氏距离。因为所有向量在单位球上（长度 = 1）：

```
‖a − b‖² = ‖a‖² + ‖b‖² − 2(a·b) = 1 + 1 − 2cosθ = 2 − 2cosθ

d = √(2 − 2cosθ)
```

换算表（实算）：

| 余弦 | 欧氏距离 | 含义 |
|---:|---:|---|
| 1.000 | 0.000 | 完全相同 |
| 0.900 | 0.447 | 很像 |
| 0.744 | 0.716 | ← 实测：夜间同地点对 |
| 0.663 | 0.821 | ← 实测：夜间全体平均 |
| 0.500 | 1.000 | 中等 |
| 0.000 | 1.414 | 垂直 |

因为特征全非负（M2），余弦 ∈ [0,1]，所以**距离范围是 0 ~ 1.414**。

代入 baseline 实测：

```
d(a,p) = 0.716
d(a,n) = 0.821
        ─────────
当前距离差 = 0.105     而 margin 要求 ≥ 0.200
```

> **margin=0.2 相当于要求把当前的判别间隙撑到约 1.9 倍。**

这把抽象超参翻译成了人话，并且能判断它**合理**：既不是小到等于没约束，也不是大到离谱（比如 margin=1.0 在总范围只有 1.414 的空间里几乎不可能达到，会导致所有三元组永远有巨大 loss，训练不稳定）。

> 📌 被问"margin 怎么定的"，多数人只能答"经验值/试出来的"。能做这个换算，说明你理解了它的几何含义。

---

## 6. 为什么必须 L2 归一化（否则模型会作弊）⭐

假设**不做**归一化。模型想降 loss，有个极省力的办法：

> **把所有输出向量都乘以 10。**

所有距离放大 10 倍：`d(a,p)` 0.7→7，`d(a,n)` 0.8→8，距离差从 0.1 变成 **1.0**，轻松超过 margin，loss 归零。

**但相对关系一点没变。** 这是纯粹的**作弊解（degenerate solution）**：数学上完美降低 loss，任务上毫无意义。

L2 归一化把向量**强制钉在单位球面上**，"整体放大"这条路被堵死。模型想降 loss 只剩一条路：**真的改变向量方向**，即真的学到判别性。

> 📌 "为什么要 L2 归一化"，多数人答"让点积等于余弦"就停了。接着说出"更重要的是它堵死了缩放作弊，让 margin 有确定的尺度"，深度完全不同。

## 7. 三元组怎么造（`triplet_dataset.py`）

```python
positive_candidates = [p for p in db if abs(idx(p) - anchor_idx) <= 3]    # positive_tolerance
negative_candidates = [p for p in db if abs(idx(p) - anchor_idx) >= 20]   # negative_gap
positive_path = random.choice(positive_candidates)
negative_path = random.choice(negative_candidates)
```

anchor = `Image050` 时的采样区间：

```
帧号: 0 ......... 30 |31 ...46| 47 48 49 [50] 51 52 53 |54 ... 69| 70 ......... 99
      └─ 负样本候选 ─┘ └ 灰色 ┘ └─── 正样本候选 ───┘ └ 灰色 ┘ └─ 负样本候选 ─┘
         (差 ≥ 20)     (排除)        (差 ≤ 3)          (排除)      (差 ≥ 20)
```

### 7.1 三个参数，三个设计意图

**① `positive_tolerance = 3`：与评测的 tolerance 一致**

> **训练时定义的"正确"，必须和评测时定义的"正确"是同一个标准。**

否则优化目标和衡量目标错位。这叫**训练目标与评测指标对齐**，基本但常被忽略。

**② `negative_gap = 20`：中间留了一段"灰色地带"**

帧号差 4~19 的图像很尴尬：

- 物理上**离得挺近**，视野可能有重叠，看起来相当像
- 但按评测标准（±3）算**错误**

拿它们当负样本 = 教模型"把两张看起来很像、物理上也很近的图推远"——**矛盾且带噪的信号**。

`negative_gap=20` 划了一条安全线：**只用明确不同的地点当负样本**。

> 📌 能体现思考深度的设计点。面试可说：「正负样本之间我留了缓冲区，帧号差 4 到 19 的既不当正也不当负，因为那是物理上很近但按评测标准算错的灰色地带，拿来当负样本会给模型矛盾信号。」

**③ `random.choice`：每次重新随机**

`__getitem__` 每次调用都重新随机挑正负样本 → 同一 anchor 每个 epoch 配到的组合不同，相当于**隐式数据增强**。虽然只有 100 个 anchor，三元组组合数远大于 100。

（对应地 `train_triplet.py` 用 `shuffle=True`，抽特征用 `shuffle=False`——训练要打破顺序相关性，推理不需要。）

## 8. 训练循环逐行（`train_triplet.py`）

```python
for batch in loader:
    anchor   = batch["anchor"].to(device)        # [16, 3, 224, 224]
    positive = batch["positive"].to(device)
    negative = batch["negative"].to(device)

    anchor_features   = model(anchor)            # ← 第 1 次 forward
    positive_features = model(positive)          # ← 第 2 次
    negative_features = model(negative)          # ← 第 3 次

    loss = criterion(anchor_features, positive_features, negative_features)

    optimizer.zero_grad()
    loss.backward()
    optimizer.step()

    total_loss += loss.item() * anchor.size(0)
```

### 8.1 三次 forward = 孪生（Siamese）结构

**同一个模型跑三次**，不是三个模型。三个分支**共享同一套权重**——必须共享，否则 anchor 和 positive 会被映射到两个不同的空间，距离失去意义。

> ⚠️ **但"分三次 forward"这个写法本身有隐患**：anchor 全是夜间图、positive/negative 全是白天图，三次 forward 每次面对的都是**域分布完全不同**的一批数据。结合 M3 讲的 BatchNorm 行为，后果不小。**这是 M7 的重头戏。**

### 8.2 三行标准动作

```python
optimizer.zero_grad()   # ① 清空上一步残留的梯度
loss.backward()         # ② 反向传播算梯度
optimizer.step()        # ③ 用梯度更新参数
```

**为什么必须 `zero_grad`**：PyTorch 的梯度是**累加**的（`param.grad += 新梯度`）。不清零会带着上一步的梯度一起更新，方向就错了。

（这个累加设计是特性不是 bug——显存不够时可以跑几个小 batch 累积梯度再更新一次，模拟大 batch，叫**梯度累积**。）

### 8.3 `loss.item() * anchor.size(0)` 为什么要乘回去

`TripletMarginLoss` 默认返回 **batch 内平均值**。直接累加平均值的话，最后一个不满的 batch（如 4 个样本）会和满 batch（16 个）**权重相同**，epoch 平均 loss 就偏了。

乘回 batch size 得到"总和"，最后除以 `len(loader.dataset)` 才是正确的加权平均。

### 8.4 `.item()` 必须加

直接 `total_loss += loss` 会累加一个**还挂着计算图的 tensor**，整个 epoch 的计算图都留在显存里，几十步就 OOM。`.item()` 取出 Python 数字，切断引用。

## 9. 随机负样本的根本问题 ⚠️（M7 伏笔）

回到 §4 那个"双刃剑"：**满足 margin 后 loss 归零，不产生梯度**。

那随机挑的负样本，有多少比例"太容易"？用预训练模型实测（模拟一个 epoch 的 100 个三元组）：

```
平均 d(anchor, positive) : 0.724
平均 d(anchor, negative) : 0.850
平均 loss                : 0.0954
loss == 0 的三元组       : 24 / 100 = 24.0%     ← 完全不产生梯度
```

**训练刚开始就有 24% 的三元组白跑。** 随着训练推进模型变强，这个比例会**迅速上升**——很快大部分 batch 在空转，loss 曲线漂亮地降到接近 0，但模型已经不怎么学东西了。

根本原因：随机抽的负样本大多是"相隔 50 帧的完全不同的地方"，模型闭眼都能区分。**真正有价值的是那些长得像但其实不是同一地点的负样本。**

改用**最难负样本**（候选里挑离 anchor 最近的）实测对比：

| 采样策略 | 平均 loss | loss=0 比例 |
|---|---:|---:|
| **随机负样本**（当前实现） | 0.0954 | **24%** |
| **最难负样本** | 0.1685 | **1%** |

**训练信号强 1.8 倍，浪费的三元组从 24% 降到 1%。**

这就是 **hard negative mining（难负样本挖掘）**，是 triplet 训练的标配，NetVLAD 论文花了大量篇幅讲它。

> ⚠️ 但别无脑上最难的：只挑最难的容易挑到**标注噪声**或**真正无法区分**的样本，导致训练崩溃（模型被逼着区分本来就该相似的东西）。实践常用 **semi-hard negative**——挑"比 positive 远，但仍在 margin 范围内"的负样本，既有信号又不极端。这是 FaceNet 论文的做法。

## 10. 面试怎么答

### Q1：讲讲你的训练部分。

> 我用 triplet loss 做度量学习。三元组是：夜间图当 anchor，同一位置正负 3 帧内的白天图当 positive，帧号差 20 以上的白天图当 negative。loss 是 `max(0, d(a,p) − d(a,n) + margin)`，margin 取 0.2，距离用欧氏距离。因为特征做了 L2 归一化，在单位球上距离和余弦有 `d = √(2−2cos)` 的关系，我算过 0.2 的 margin 大概相当于要求把当前的判别间隙撑到 1.9 倍。
>
> 训练目标很具体：baseline 里夜间的判别间隙只有 0.081，是白天的一半，我要做的就是把它撑开。

### Q2 ⭐：为什么用度量学习，不把每个地点当一个类做分类？

> 两个原因。一是地点是开放集，机器人会去新地方，分类器的输出层是固定的，来了新地点就得重训；度量学习学的是"怎么把图像变成向量"，新地点直接抽特征入库，模型完全不用动。二是我要回答的问题本来就是"这两张是不是同一地点"，是个关系判断而不是分类。
>
> 不过要补一句，CosPlace 那篇 CVPR 2022 恰恰是把 VPR 当分类做的，按 GPS 和朝向分组当类别用大间隔 softmax，效果很好，动机就是绕开三元组挖掘的开销。所以准确说是在我这个规模下度量学习更自然，不是分类不行。

### Q3 ⭐：margin 是怎么定的？0.2 意味着什么？

（见 §5，做那个几何换算。这题能拉开很大差距）

### Q4 ⭐：为什么必须做 L2 归一化？不做会怎样？

> 除了让点积等于余弦之外，更重要的是它堵死了一条作弊路径。如果不归一化，模型可以简单地把所有输出向量放大 10 倍——所有距离都放大 10 倍，距离差从 0.1 变成 1.0，轻松超过 margin=0.2，loss 归零，但相对关系一点没变，什么都没学到。这是个数学上完美、任务上无意义的退化解。归一化把向量钉在单位球上，模型只能真的改变方向，而且 margin 在球面上处处是同一个尺度。

### Q5：正负样本的阈值 3 和 20 是怎么定的？

> positive 用 ±3 是为了和评测时的 tolerance 完全一致——训练时定义的"正确"必须和衡量时的"正确"是同一个标准，否则优化目标和评测目标就错位了。
>
> negative 用 ≥20 是刻意留了一段缓冲区。帧号差 4 到 19 的图像很尴尬：物理上离得很近、视野可能还有重叠、看起来相当像，但按评测标准算错误。如果拿它们当负样本，等于在教模型把两张看起来很像、物理上也很近的图推远，这是矛盾的信号。所以我只用明确不同的地点当负样本。

### Q6 ⭐：你的负样本是随机选的，这样有问题吗？

> 有，而且我量化过。triplet loss 有个特性：一旦满足了 margin，loss 就归零，完全不产生梯度。随机选的负样本大多是相隔几十帧的完全不同的地方，模型很容易区分。我用预训练特征模拟了一个 epoch，**训练刚开始就有 24% 的三元组 loss 已经是 0**，随着训练推进这个比例还会迅速上升，等于大部分 batch 在空转——loss 曲线看起来降得很漂亮，但模型没在学东西。
>
> 我对比测了如果改用最难负样本，平均 loss 从 0.095 涨到 0.169，零梯度三元组从 24% 降到 1%，训练信号强 1.8 倍。这就是 hard negative mining，是 triplet 训练的标配。不过不能无脑挑最难的，容易挑到标注噪声或本来就无法区分的样本导致训练崩，实践中一般用 semi-hard——挑比 positive 远但还在 margin 内的。

### Q7：为什么是三次 forward？能优化吗？

> 三次 forward 用的是同一个模型，也就是孪生结构，三个分支共享权重——必须共享，否则 anchor 和 positive 会被映射到不同空间，距离没有意义。
>
> 能优化，而且应该优化：把三批图 `cat` 成一个 `[3B]` 的大 batch 只 forward 一次，再切开算 loss。这样一是快，二是更重要——现在 anchor 全是夜间图、positive/negative 全是白天图，分三次 forward 意味着 BatchNorm 每次看到的都是域分布完全不同的一批数据，统计量是被污染的。合成一个 batch 能让 BN 看到混合分布。（详见 M7）
