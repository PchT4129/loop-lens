> 这一章讲清它在算什么、为什么用 F 而不是 E、以及那个"昼夜配对判别力接近随机"的更深解释。

## 1. 相机模型：3D 点怎么变成像素

### 1.1 针孔模型两步走

**第一步：透视除法**（"相机"的本质）

```
x = X / Z
y = Y / Z
```

除以深度——远的东西看起来小。得到的 `(x,y)` 叫**归一化坐标**。

**第二步：乘内参矩阵**（物理单位 → 像素）

```
        ⎡ fx   0   cx ⎤
K =     ⎢  0  fy   cy ⎥        u = fx·x + cx
        ⎣  0   0    1 ⎦        v = fy·y + cy
```

| 参数 | 含义 |
|---|---|
| `fx, fy` | 焦距（像素单位）。决定视场角——越大视野越窄 |
| `cx, cy` | 主点，光轴与图像平面交点，通常≈图像中心 |

实测：

```
K = [[800,0,320],[0,800,240],[0,0,1]]，  3D 点 P = [1.0, 0.5, 4.0]

归一化: x = 1.0/4.0 = 0.25,  y = 0.5/4.0 = 0.125
乘内参: u = 800×0.25+320 = 520,  v = 800×0.125+240 = 340
```

齐次写法就是 `K @ P` 再除以第三个分量。

### 1.2 ⭐ 这里藏着单目 SLAM 最核心的困难

> **`x = X/Z` 这个除法把深度消掉了。**

3D 点在 `(1,0.5,4)` 和在 `(2,1,8)`——**投影到图像上是同一个像素**。

**单张图像无法确定深度，也无法确定绝对尺度。** 看一张照片分不清是"小模型近距离拍"还是"真实建筑远距离拍"。

**这就是 M8 讲的"单目回环要用 Sim(3) 而非 SE(3)"的根源。**

### 1.3 畸变

真实镜头还有**径向畸变** `k1,k2,k3`（桶形/枕形）和**切向畸变** `p1,p2`。标定就是求 `K` 和这些系数，用棋盘格标定板。

**本项目没有标定信息**——这决定了 §2.3 的选择。

## 2. 对极几何

### 2.1 直觉：为什么两个视图之间有约束

位置 1 拍一张、位置 2 拍一张。图 1 上有个点 `p1`。**它对应的 3D 点在图 2 的哪里？**

你不知道深度，所以那个 3D 点可能在"从光心 1 出发穿过 `p1` 的射线"上的**任何位置**。

**但这条射线投影到图 2 上，是一条直线。**

> **`p1` 的对应点一定落在图 2 的某条特定直线上**，这条线叫**对极线（epipolar line）**。
>
> **搜索范围从二维平面降到一维直线——这就是对极约束的全部意义。**

### 2.2 数学形式

```
x₂ᵀ · E · x₁ = 0
```

`E = [t]× R` 叫**本质矩阵**，`[t]×` 是平移向量的**反对称矩阵**（把叉乘写成矩阵乘法）。

**为什么等于 0？** 相机 1 光心、相机 2 光心、那个 3D 点**三点共面**（对极平面）。三向量共面 ⟺ 混合积为 0，展开即得。

### 2.3 ⭐ E 和 F 的区别——本项目的关键选择

| | 作用于什么坐标 | 需要标定吗 |
|---|---|---|
| **本质矩阵 E** | **归一化坐标** `x` | **需要**（要用 `K` 转换） |
| **基础矩阵 F** | **像素坐标** `p` | **不需要** |

```
F = K⁻ᵀ · E · K⁻¹
```

**`geometric_verification.py` 用 `findFundamentalMat` 是正确选择**——Gardens Point 没有标定信息，拿不到 `K`。

**F 同样施加对极约束**，足以判断"是不是同一场景"；只是解不出物理的 `R,t`。**而几何验证只需要内点数，不需要位姿。**

> 📌 被问"为什么用基础矩阵不用本质矩阵"：**没有标定，而且验证任务不需要恢复位姿。**

### 2.4 实测验证

60 对已知正确的匹配：

```
|x₂ᵀ E x₁| 平均 = 1.568e-17   ← ≈0 ✓
|p₂ᵀ F p₁| 平均 = 2.845e-17   ← ≈0 ✓
把匹配打乱后再算  = 6.592e-02   ← 明显不为 0
```

> 📌 **这就是 RANSAC 判定内点的依据**：算 `|p₂ᵀFp₁|`（实际用点到对极线的距离），小于阈值即内点。

## 3. 从 E 恢复 R, t，以及尺度歧义

### 3.1 求解方法

- **8 点法**：F 有 9 个元素、8 个自由度（尺度无关），线性解需 8 对点
- **5 点法**：E 只有 5 个自由度（3 旋转 + 2 平移方向），已知 `K` 时 5 对点即可，更鲁棒

SVD 分解 E 得到 **4 组** `(R,t)` 候选，用"3D 点必须在两相机前方"（cheirality check）筛出唯一正确的。

### 3.2 实测

```
恢复的 R：旋转误差 = 0.0000 度                 ← 完美
恢复的 t = [0.9806, 0, 0.1961]  模长 1.0000
真值   t = [0.5,    0, 0.1   ]  模长 0.5099
方向夹角 = 0.0000 度                           ← 方向完全正确
```

> ⚠️ **方向对，长度不对**——这就是**尺度歧义**。因为 `E = [t]×R` 里 `t` 乘任何常数，对极约束依然成立。

**物理解释**：场景放大 2 倍、相机间距也放大 2 倍，拍出来**一模一样**。

**怎么解决**：双目（基线已知）、RGB-D（直接测深度）、IMU（积分位移）、已知尺寸物体。

## 4. PnP：回环检测的首选

> **已知一批 3D 点及其像素坐标，求相机位姿。**

实测对比：

```
E 分解:  t = [0.9806, 0, 0.1961]   模长被归一化      ← 尺度丢失
PnP:     t = [0.5, 0, 0.1]         平移误差 0.000000  ← 尺度正确
```

**为什么 PnP 有尺度？** **3D 点本身提供了绝对长度参考。**

> 📌 **这就是 M8 说"回环检测最常用 PnP"的原因**：历史关键帧建图时**已三角化出地图点**（3D），当前帧特征（2D）与之匹配后直接 PnP 就能解出**带尺度的完整位姿**，可直接送进位姿图。用 E 分解得到的位姿没有尺度，还要另想办法对齐。

（常用求解器 **EPnP**；最少 3 对点有解（P3P），4 对点唯一确定。）

---

## 5. 三角化

PnP 的逆问题：**已知两相机位姿 + 同一 3D 点在两图的像素坐标，求 3D 位置。**

从两个光心各引一条射线穿过对应像素，**交点**就是 3D 点。（实际有噪声，两线不精确相交，求"到两线距离平方和最小"的点，用 SVD 解。）

**SLAM 建图就靠它**：前端估位姿 → 三角化出地图点 → 新帧用 PnP 定位 → 再三角化更多点……

> ⚠️ **精度依赖视差（parallax）**：两相机太近时射线几乎平行，交点极不稳定。**这是关键帧选择要求"移动足够远"的原因**（M8 §1.1）。

## 6. 位姿表示

平移简单（3 个数）。**麻烦的是旋转**——3 个自由度，但没有一种"3 个数"的表示是完美的。

### 6.1 四种表示（实测同一个绕 Y 轴 15° 的旋转）

| 表示 | 值 | 参数数 | 问题 |
|---|---|---|---|
| **旋转矩阵** | 3×3 | 9 | 冗余，需满足 `RᵀR=I, det=1`，不好直接优化 |
| **轴角/旋转向量** | `[0, 0.2618, 0]` | 3 | 方向=转轴，模长=转角。**紧凑无冗余** |
| **四元数** | `[0, 0.1305, 0, 0.9914]` | 4 | 约束 `‖q‖=1`。**无奇异点，插值方便** |
| **欧拉角** | `[0, 15, 0]°` | 3 | 直观，**但有万向锁** |

### 6.2 万向锁实测 ⭐

```
输入 [0, 90, 0]  → 转矩阵再转回 → [-0,  90, 0]
输入 [0, 90, 30] → 转矩阵再转回 → [-30, 90, 0]    ← 30 跑到第一个位置
输入 [0, 90, 60] → 转矩阵再转回 → [-60, 90, 0]
```

**pitch=90° 时 roll 和 yaw 不可区分**——转 roll 30° 和转 yaw 30° 产生相同旋转，**丢失一个自由度**。这就是**万向锁（gimbal lock）**。

> 📌 **SLAM 里从不用欧拉角做内部表示**（只在给人看时转换）。用四元数存储，用李代数优化。

### 6.3 李群与李代数——为什么优化需要它

**问题**：优化要做"当前位姿 + 小增量"，但旋转矩阵**不能直接加**（相加后不再是旋转矩阵）。

- **李群 SO(3)**：所有 3D 旋转矩阵构成的群，是个**流形**（弯曲空间），只能"乘"不能"加"
- **李代数 so(3)**：该流形在单位元处的**切空间**，是普通 3 维向量空间（就是轴角），**可以自由加减**

```
R = exp(φ∧)        李代数 φ (3维向量) → 李群 R (旋转矩阵)
φ = log(R)∨        反向
```

**优化套路**：

```
1. 在【李代数】里算增量 Δφ（3 维向量，可加减、可求导）
2. exp 映射回【李群】：R_new = exp(Δφ∧) · R_old
3. 重复
```

> 📌 **李代数让"在弯曲空间上优化"变成"在平直空间上优化"。**
>
> 对应地 `SE(3)`（旋转+平移，6 维）和 `Sim(3)`（再加尺度，7 维，单目回环用它）也有各自的李代数。

## 7. 非线性优化：后端在算什么

### 7.1 优化目标：重投影误差

```
重投影误差 = ‖ 把 3D 点用当前位姿投影到图像 − 实际观测的像素 ‖
```

实测：

```
用真值位姿    : 平均 0.000000 像素
位姿加一点扰动 : 平均 35.11 像素
```

```
min Σ ‖ π(K, R, t, P_i) − p_i ‖²
```

这是**非线性最小二乘**。

### 7.2 怎么解

| 方法 | 思路 |
|---|---|
| **高斯牛顿 GN** | 当前点线性化，解正规方程 `JᵀJ·Δx = −Jᵀr`，迭代 |
| **LM** | GN + 阻尼：`(JᵀJ + λI)·Δx = −Jᵀr`。λ 大时接近梯度下降（稳），小时接近 GN（快）。**更鲁棒，实际常用** |

`J` 是雅可比。**关键性质：`JᵀJ` 稀疏**——每个观测只涉及一个位姿和一个地图点。利用稀疏性（Schur 补消元）才能让大规模 BA 跑得动。

### 7.3 BA vs 位姿图优化

| | 优化什么 | 规模 | 用在哪 |
|---|---|---|---|
| **Bundle Adjustment** | 位姿 **+ 地图点** | 大 | 局部建图、最终全局优化 |
| **位姿图优化** | **只有位姿**，地图点固定 | 小得多 | **回环发生时**（M8 §6） |

**回环时先做位姿图优化**（规模小、快速摊平误差），之后可再跑全局 BA 精修。

求解器：**g2o**（ORB-SLAM）、**GTSAM**（因子图，Kimera）、**Ceres**（VINS-Fusion）。

## 8. 回到本项目

```python
_, mask = cv2.findFundamentalMat(src, dst, cv2.FM_RANSAC, ransac_threshold, 0.99)
```

| 代码 | 原理 |
|---|---|
| 用 `Fundamental` 而非 `Essential` | **没有相机标定**拿不到 `K`；验证只需内点数不需要位姿 |
| `FM_RANSAC` 在做什么 | 随机抽 8 对点算 F → 用点到对极线距离检验所有匹配 → 数内点 → 重复取最优 |
| `ransac_threshold=3.0` | 点到对极线的距离阈值，单位**像素** |
| `0.99` | 置信度，决定 RANSAC 迭代次数 |
| 内点数为何能判断"同一地点" | **正确匹配都服从同一对极几何**（来自同一真实三维场景），错误匹配随机散落 |
| 为何至少 8 对点 | F 有 8 个自由度，8 点法的最低要求 |

### 8.1 那个"判别力接近随机"的更深解释 ⭐

实测发现：ORB 在昼夜配对上正确 25.1 内点 vs 错误 24.4，接近随机。现在能解释得更深：

> 那几十个"匹配"本身就是虚假的。而 **F 有 8 个自由度，在几十个随机点里拟合出一个"看似成立"的模型并不困难**——这就是内点数失去判别力的原因。
>
> **不是 RANSAC 失效了，是喂给它的匹配本身就是噪声。** 问题出在 ORB 描述子扛不住光照剧变，不在几何验证这一步。

这个区分很重要：它把"几何验证没用"修正成"**局部特征不行，几何验证无米下炊**"，直接指向正确的下一步——SuperPoint + LightGlue。

## 9. 面试怎么答

### Q1：讲讲相机的针孔模型。

> 3D 点投影分两步。第一步透视除法，`x=X/Z, y=Y/Z`，除以深度，这是"远小近大"的来源，得到归一化坐标。第二步乘内参矩阵 K，`u=fx·x+cx`，把物理单位换算成像素。fx、fy 是焦距决定视场角，cx、cy 是主点通常在图像中心。
>
> 关键是那个除法把深度消掉了——3D 点在 (1,0.5,4) 和 (2,1,8) 投影到同一个像素。**这就是单目丢失绝对尺度的根源**，也是单目回环要用 Sim(3) 而不是 SE(3) 的原因。

### Q2 ⭐：什么是对极约束？

> 图 1 上一个点，因为不知道深度，它对应的 3D 点可能在一条射线上的任何位置。但这条射线投影到图 2 上是一条直线，所以对应点一定落在这条对极线上——**搜索范围从二维平面降到一维直线**。
>
> 数学形式是 `x₂ᵀEx₁=0`，E 是本质矩阵等于 `[t]×R`。几何上它表达的是两个光心和 3D 点三点共面，共面就意味着混合积为零。
>
> RANSAC 判内点用的就是这个：算点到对极线的距离，小于阈值就是内点。我验证过，用真实匹配算出来是 1e-17 量级，把匹配打乱后变成 6.6e-02。

### Q3 ⭐：本质矩阵和基础矩阵的区别？你为什么用基础矩阵？

> E 作用在归一化坐标上，需要相机内参；F 作用在像素坐标上，不需要标定，两者关系是 `F = K⁻ᵀEK⁻¹`。我用 F 是因为 Gardens Point 数据集没有标定信息，拿不到 K；而且几何验证只需要内点数来判断是不是同一场景，不需要恢复位姿，所以 F 完全够用。

### Q4：为什么单目恢复不出尺度？

> 因为 `E = [t]×R` 里 t 乘任何常数对极约束都成立。物理上说，把整个场景和相机间距同时放大两倍，拍出来的照片一模一样。我实测过，从 E 分解出的 t 方向完全正确但模长被归一化成 1，真值模长是 0.51。要解决就得引入外部信息：双目的已知基线、RGB-D 的深度、IMU 积分，或者已知尺寸的物体。

### Q5：回环检测为什么用 PnP 而不是分解本质矩阵？

> PnP 是已知 3D 点和它们的像素坐标求位姿，因为 3D 点提供了绝对长度参考，**解出来的位姿是带尺度的**。我实测过 PnP 的平移误差是 0，而 E 分解的模长被归一化。回环检测里历史关键帧在建图时已经三角化出地图点了，当前帧提取特征跟它们匹配，直接 PnP 就能得到完整位姿送进位姿图。

### Q6 ⭐：旋转有哪些表示？为什么 SLAM 不用欧拉角？

> 四种：旋转矩阵 9 个数但有正交约束；轴角 3 个数紧凑；四元数 4 个数无奇异点、插值方便；欧拉角 3 个数最直观但有万向锁。
>
> 万向锁是说某个角到 90 度时会丢失一个自由度。我实测过，输入欧拉角 `[0,90,30]`，转成矩阵再转回来变成 `[-30,90,0]`——roll 和 yaw 完全混在一起了。所以 SLAM 里用四元数存储，优化时用李代数。

### Q7 ⭐：为什么优化位姿要用李代数？

> 因为旋转矩阵不能直接相加——两个旋转矩阵加起来不再满足正交约束，不是合法旋转了。而优化的本质就是"当前值加一个增量"。
>
> 李群 SO(3) 是所有旋转矩阵构成的流形，是弯曲空间，只能乘不能加；李代数 so(3) 是它在单位元处的切空间，是个普通的三维向量空间，可以自由加减求导。所以做法是在李代数里算增量，再用指数映射回李群去更新。**本质上是把"在弯曲空间上优化"变成"在平直空间上优化"。**

### Q8：SLAM 后端优化的目标函数是什么？怎么解？

> 重投影误差——把 3D 点用当前估计的位姿投影到图像上，和实际观测的像素做差，最小化所有误差的平方和。这是非线性最小二乘，用高斯牛顿或 LM 迭代。LM 加了阻尼项，λ 大时接近梯度下降更稳，λ 小时接近高斯牛顿更快，实际用得更多。
>
> 关键是 `JᵀJ` 是稀疏的，因为每个观测只涉及一个位姿和一个地图点，利用稀疏性做 Schur 补消元才能让大规模 BA 跑得动。
>
> 另外要区分 BA 和位姿图优化：BA 同时优化位姿和地图点，规模大；位姿图只优化位姿，规模小得多，**回环时先用它快速把误差摊平**，之后可以再跑全局 BA 精修。
