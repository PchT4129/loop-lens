# 附录 I · Softmax 与交叉熵

> 第一梯队 ④（收尾）。本项目用的是 triplet loss，没直接用交叉熵——
> 但它是任何 DL 岗的必考题，**而且它正是"为什么 VPR 用度量学习而不用分类"这个问题的对照面**。
> 讲清交叉熵，才能真正说清 triplet loss 好在哪、差在哪，以及 CosPlace 为什么能用分类做 VPR。

---

## 1. 问题设定

分类网络最后一层输出一堆**任意实数**，叫 **logits**：`[2.0, 1.0, 0.1]`。

可能是负数、可能很大、和不等于 1。但我们要的是**概率分布**。

**所以需要一个函数把任意实数变成概率分布。** 这就是 Softmax。

---

## 2. Softmax

```
softmax(z_i) = exp(z_i) / Σ_j exp(z_j)
```

实测：

```
logits  : [2.0, 1.0, 0.1]
softmax : [0.6590, 0.2424, 0.0986]
和 = 1.0000 ✓
```

### 2.1 为什么用 `exp`

| 理由 | 说明 |
|---|---|
| **保正** | `exp` 值域 `(0,+∞)`，概率不会为负 |
| **保序** | `exp` 单调递增，logits 大的概率也大 |
| **放大差距** ⭐ | 见下 |

实测放大效果：

```
logits 差 1 -> softmax [0.7311, 0.2689]     差 2.7 倍
logits 差 3 -> softmax [0.9526, 0.0474]     差 20 倍
logits 差 6 -> softmax [0.9975, 0.0025]     差 399 倍
```

**logits 只差 6，概率差近 400 倍。** 这个放大是刻意的——让模型判断**果断**而非模棱两可。

（名字由来：它是 `max` 的**平滑（soft）版本**。真正的 max 输出硬邦邦的 `[1,0,0]` 不可导；softmax 平滑可导，同时保留"突出最大值"的效果。）

---

## 3. 数值稳定性：减去最大值

朴素实现会**溢出**（实测）：

```
z = [1000, 999, 998]
exp(1000) = inf
朴素 exp(z)/sum(exp(z)) = [nan, nan, nan]     ← 崩了
```

**修法**利用恒等式：

```
softmax(z) = softmax(z − c)      对任意常数 c 成立
```

（分子分母同乘 `exp(−c)`，约掉。）

取 `c = max(z)`，最大项变成 `exp(0)=1`，其余 `<1`，永不溢出：

```
z − max(z) = [0, -1, -2]
结果 = [0.6652, 0.2447, 0.0900]     ← 与 PyTorch 内置一致 ✓
```

> 💡 被问"softmax 有什么数值问题"：**"exp 会溢出，标准做法是先减去最大值，利用 softmax 的平移不变性。"**

---

## 4. 交叉熵

### 4.1 信息论来源

**熵**衡量分布的不确定性（最优编码下平均需要多少比特）。

**交叉熵**衡量：**用分布 `q` 设计的编码去编码真实分布 `p` 的数据，平均需要多少比特**。

```
H(p, q) = − Σ p_i · log(q_i)
```

`q` 越接近 `p` 越小。**最小化交叉熵 = 让预测分布逼近真实分布。**

> 常见追问：**`KL散度 = 交叉熵 − 熵`**。分类时真实标签是 one-hot，熵为 0，所以**交叉熵与 KL 散度完全等价**。

### 4.2 对 one-hot 标签的简化 ⭐

标签是 `[1,0,0]`，代入：

```
L = −(1·log q₀ + 0·log q₁ + 0·log q₂) = −log q₀
```

> **交叉熵 = −log(正确类的预测概率)。**
> **它只看正确类那一项，公式里根本没有错误类。**

很多人以为交叉熵在"同时压低错误类"——其实错误类是通过 **softmax 的分母**被间接压低的，不在 loss 公式里。

---

## 5. 为什么是 `−log`

实测：

```
正确类的预测概率  |  −log(p)  |  含义
0.990            |  0.0101   |  非常自信且正确
0.900            |  0.1054   |  自信且正确
0.500            |  0.6931   |  犹豫
0.100            |  2.3026   |  答错了
0.010            |  4.6052   |  自信地答错
0.001            |  6.9078   |  极度自信地答错
```

**两个性质**：`p=1` 时 loss=0；`p→0` 时 loss→∞。

> 📌 **交叉熵的核心性格：极度厌恶"自信的错误"，且惩罚无上限。**

**对比 MSE**：预测 0.001 与真实 1 的平方误差是 0.998，预测 0.1 时是 0.81——**MSE 对离谱错误惩罚不够，而且配 sigmoid 时梯度会消失**。这就是分类不用 MSE 的原因。

---

## 6. 梯度极其优雅 ⭐ 高频面试题

Softmax + 交叉熵组合求导：

```
∂L/∂z_i = p_i − y_i
```

**预测概率 减去 真实标签。** 实测验证：

```
logits    : [2.0,    1.0,    0.1   ]
softmax p : [0.6590, 0.2424, 0.0986]
one-hot y : [1.0,    0.0,    0.0   ]
p − y     : [-0.341, 0.2424, 0.0986]
实际梯度   : [-0.341, 0.2424, 0.0986]
一致: True ✓
```

**为什么这么简洁？** 交叉熵里的 `log` 把 softmax 里的 `exp` 消掉了，中间复杂项全部约掉。**这不是巧合，是两者被设计成一对的原因。**

**直觉**：`p − y` = "预测偏离真实多少，就往回推多少"。

- 正确类：`0.659 − 1 = −0.341` → 负梯度 → 把 `z₀` **推高**
- 错误类：`0.242 − 0 = +0.242` → 正梯度 → 把 `z₁` **压低**

而且**梯度大小正比于错误程度**——越离谱梯度越大。这是很健康的性质（对比 sigmoid+MSE：越离谱梯度反而越小，梯度消失）。

## 7. PyTorch 的高频 bug

```
正确用法 CrossEntropyLoss(logits)          loss = 0.1967
错误用法 CrossEntropyLoss(softmax(logits)) loss = 0.6740
```

> ⚠️ **`nn.CrossEntropyLoss` 内部已包含 softmax。模型最后一层【不要】再加 softmax。**

等价关系（实测）：

```
CrossEntropyLoss(logits)         = 0.196734
NLLLoss(LogSoftmax(logits))      = 0.196734
−log(softmax(logits)[正确类])     = 0.196734
```

```
CrossEntropyLoss = LogSoftmax + NLLLoss
```

**双重 softmax 的后果**：不报错，但 logits 被压平到 `(0,1)`，类间差距抹平，**梯度大幅变小，训练变慢甚至学不动**。又一个**静默失效**（和 M5 评测 bug、A5 那三个坑同类）。

> 💡 **记法**：`CrossEntropyLoss` 吃 **logits**；`NLLLoss` 吃 **log 概率**。

### 7.1 为什么用 `log_softmax` 而不是 `log(softmax(x))`

实测（logits = `[-100, 0]`）：

```
log(softmax(x)) = [-99.983, 0.0]      ← 精度已损失
log_softmax(x)  = [-100.0,  0.0]      ← 准确
```

先 `exp` 再 `log` 引入精度损失（这里差 0.017；数值更极端时直接变 `-inf`）。**`log_softmax` 在内部把 log 和 exp 做了数学化简**，绕过中间的 exp。

## 8. 回到本项目：为什么不用分类 ⭐

M6 答过这个问题，但当时没有对照面。现在有了。

### 8.1 完整对比

| | **交叉熵分类** | **Triplet Loss** |
|---|---|---|
| 优化目标 | 把样本**分对类** | **相对距离关系** |
| 输出 | 类别概率（维度=类别数） | 一个向量 |
| 新类别 | **要改输出层 + 重训** | **直接抽特征入库，模型不动** |
| 对特征的约束 | 只要**可分**就行 | **显式约束距离** |
| 梯度行为 | `p − y`，**永远有梯度** | 满足 margin 后**归零** |

### 8.2 第四行最微妙也最值钱

> **交叉熵只要求特征"可分"，不要求"同类紧凑"。**

二维平面上两类点，只要能被一条直线分开交叉熵就满意了——**哪怕同类点散得到处都是**。

但检索需要的恰恰是"同类紧凑"：靠**距离**排序，而不是靠分界线判别。**"能被分开"和"距离上足够近"是两回事。**

这就是为什么 M2 量化的**类内/类间相似度差距**（白天 0.157、夜间 0.081）是有意义的指标——它衡量的正是交叉熵不管的那个东西。

### 8.3 CosPlace 为什么能用分类做 VPR（M6 那个补丁的完整版）

**ArcFace / CosFace 这类 margin-based softmax** 在 softmax 里加入**角度间隔**：

```
普通 softmax:   logit = w·x            (等价于 |w||x|cosθ)
CosFace:        logit = s·(cosθ − m)    ← 正确类 logit 人为减去 margin
ArcFace:        logit = s·cos(θ + m)    ← 在角度上加 margin
```

**给正确类的分数人为扣掉一点，逼网络把它推得更高才能满足。** 结果是同类特征被压得**更紧凑**、异类推得**更开**。

> 📌 **margin-based softmax 把 triplet loss 想要的"类内紧、类间远"，用分类框架实现了**，同时保留分类训练的效率优势（不需要挖三元组）。
>
> **这就是 CosPlace 能 work 的原因**——不是"分类也行"，而是"**加了 margin 的分类，补上了普通交叉熵缺的那一环**"。

### 8.4 面试完整答法

> "我用度量学习有两个理由：地点是开放集，分类器输出层固定，新地点要改结构重训；而且我要的是距离关系，交叉熵只保证类可分、不保证同类紧凑，但检索是靠距离排序的。
>
> 不过要补一句，CosPlace 那篇 CVPR 2022 就是把 VPR 当分类做的，效果很好。它用的是 CosFace 那类 margin-based softmax——在正确类的 logit 上人为减去一个 margin，逼网络把同类压得更紧、异类推得更开，等于用分类的框架实现了度量学习想要的性质，同时避免了三元组挖掘的开销。所以准确说是在我这个规模和设定下度量学习更自然，不是分类不行。"

## 9. 该知道的变体

| 变体 | 解决什么 |
|---|---|
| **Label Smoothing** | one-hot `[1,0,0]` → `[0.9,0.05,0.05]`。防止对训练标签过度自信，是一种正则化（呼应 A3） |
| **Focal Loss** | `−(1−p)^γ log(p)`。样本越容易权重越小，**让模型专注难样本**。用于类别极度不平衡的检测任务。思想与 hard negative mining 同类 |
| **BCE + Sigmoid** | 多标签分类（一张图可同时是"猫"和"室内"）。每类独立 sigmoid，不做归一化竞争 |

---

## 10. 小结

| 要点 | 内容 |
|---|---|
| **Softmax** | 任意实数 → 概率分布。`exp` 保正、保序、**放大差距**（logits 差 6 → 概率差 400 倍） |
| **数值稳定** | `softmax(z) = softmax(z−max(z))`，减最大值防 `exp` 溢出 |
| **交叉熵本质** | `H(p,q) = −Σp·log q`。one-hot 时简化成 **`−log(正确类概率)`**，**公式里没有错误类** |
| **为什么 −log** | p=1 时 0，p→0 时 →∞。**极度厌恶"自信的错误"**；MSE 惩罚不足且梯度消失 |
| **梯度** ⭐ | **`∂L/∂z = p − y`**。log 和 exp 恰好抵消，这是二者被设计成一对的原因 |
| **PyTorch 坑** | `CrossEntropyLoss` **已含 softmax**。等于 `LogSoftmax + NLLLoss`。双重 softmax **不报错**但压平梯度 |
| **对照 triplet** ⭐ | 交叉熵只保证**可分**，不保证**类内紧凑**；分类输出层固定，开放集要重训 |
| **CosPlace** | **margin-based softmax** 用分类框架实现了度量学习的性质 |
