## 2. `@K` 记号的含义

`@K` 读作 "at K"，意思是 **"只看前 K 名"**。

- `@1` = 只看第 1 名 ｜ `@5` = 只看前 5 名 ｜ `@10` = 只看前 10 名

**为什么要限定？** SLAM 里每个候选都要跑一次几何验证，很贵，实际只取前几名。**指标必须匹配你实际会用多少个。**

---

## 3. Recall@K —— "有没有"

**单个 query 的定义：**

> 前 K 名里**至少有一个**对的 → 记 **1 分**
> 一个都没有 → 记 **0 分**

**它是二值的，只有 0 和 1。** 找到 1 个对的和找到 5 个对的，得分完全一样。

对照上表：

| | 看前几名 | 有对的吗 | 得分 |
|---|---|---|---:|
| **Recall@1** | 第 1 名 Image022 ✗ | 没有 | **0** |
| **Recall@5** | 第 1~5 名全 ✗ | 没有 | **0** |
| **Recall@10** | 第 1~10 名，第 6、10 ✓ | **有** | **1** |

> **重要性质：K 越大，Recall@K 只会不变或变高，绝不会变低**（看的范围变大，之前找到的还在）。
> 这就是为什么表里永远 `R@1 ≤ R@5 ≤ R@10`。

---

## 4. Precision@K —— "有几个"

```
Precision@K = 前 K 名里对的个数 ÷ K
```

**是个比例，0 到 1 之间连续取值。**

```
Precision@5 = 0 ÷ 5 = 0.00
```

**同一个 query：`Recall@10 = 1`（成功了），但 `Precision@5 = 0.00`（前 5 名全错）。**

两个数字同时成立，不矛盾——**它们在问不同的问题**。

## 6. 三个实例对比

| Query | R@1 | R@5 | R@10 | P@5 | 怎么读 |
|---|---:|---:|---:|---:|---|
| night_050 | 1 | 1 | 1 | 0.80 | 又准又干净 |
| **night_012** | **0** | **0** | **1** | **0.00** | **找到了，但排得很差** |
| day_050 | 1 | 1 | 1 | 0.60 | 准，但列表一般 |

**night_012 是整个项目的缩影**：`R@10 = 1` 但 `R@1 = 0` —— **"不是找不到，是排不准"**。

这就是 M5 那句诊断在单个 query 上的样子。

## 7. 报告里的 51%、74% 怎么来的

上面算的是**单个 query**。报告数字是**对全部 100 个 query 取平均**。

因为 Recall@K 的单 query 得分只有 0 和 1，平均后含义特别直观：

```
Recall@1  = 0.51   ⟺   100 个 query 里，51 个的第一名是对的
Recall@5  = 0.74   ⟺   100 个 query 里，74 个的前 5 名里有对的
Recall@10 = 0.87   ⟺   100 个 query 里，87 个的前 10 名里有对的
```

> 📌 **最好的记法：Recall@K 就是"成功率"——多少比例的 query 成功了。**

`Precision@5 = 0.392` 则是每个 query 前 5 名正确比例的平均 → 平均每个 query 前 5 名里约 **1.96 个**是对的。

---

## 8. 为什么 VPR 更看重 Recall

看 night_012：`R@10 = 1` 但 `P@5 = 0`。在 SLAM pipeline 里：

```
VPR 返回 10 个候选  →  逐个跑几何验证（RANSAC 特征匹配）
                        ↓
   前 5 个：验证失败，丢弃（浪费了 5 次计算）
   第 6 个：验证通过 ✓  →  确认回环，加入位姿图
```

> **只要正确答案在候选里，几何验证就能把它捞出来。**
> **precision 低只意味着白跑几次验证——是算力成本，不是能力上限。**
> **但 recall 是 0（正确答案根本不在候选里），后面再准也救不回来。**

这就是 VPR 论文以 Recall@K 为主指标的原因。

---

## 9. ⚠️ 教科书定义 vs VPR 的定义

**信息检索的经典定义**（用 night_050 举例）：

database 有 100 张，其中 **7 张**相关（`Image047`~`Image053`）。返回 5 张，其中 4 张相关。

| 指标 | 含义 | 算式 |
|---|---|---|
| **Precision（精确率）** | 你说对的，有多少真对 | 4 ÷ **5** = 0.80 |
| **Recall（召回率）** | 真正对的，你找回了多少 | 4 ÷ **7** = 0.57 |

**记忆法：**
- **Precision 的分母是"你返回的数量"**
- **Recall 的分母是"实际存在的正确数量"**

**⚠️ VPR 里的 "Recall@K" 不是这个定义。** 它是二值的"至少命中一个"，实质是 **hit rate / success rate @K**。

**为什么改？** 下游只需要**一个**正确候选就能触发成功的几何验证。找回 4 个和 1 个，对 SLAM 价值几乎一样。

> 📌 **加分答法**：被问"你这个 Recall 是标准定义吗"——
>
> "不是。VPR 社区沿用了 recall 这个叫法，但定义是二值的——Top-K 里至少有一个正确就算成功，实质是 hit rate@K。这么定义是因为下游只需要一个正确候选，**指标定义要匹配下游任务的成功条件**。"

## 10. 常见混淆自查

| 疑问 | 答案 |
|---|---|
| Recall@5 会比 Recall@1 低吗？ | **不可能。** K 变大只会不变或变高 |
| Precision@5 会比 Precision@1 低吗？ | **会。** 靠后的名次更容易错 |
| 单 query 的 Recall@K 能是 0.5 吗？ | **不能。** 只有 0 或 1 |
| 单 query 的 Precision@5 能是 0.4 吗？ | **能。** 前 5 里 2 个对 |
| R@10=1 但 P@5=0，矛盾吗？ | **不矛盾。** night_012 就是 |
| R@1=1 但 P@5 只有 0.6，矛盾吗？ | **不矛盾。** day_050 就是 |
| **Recall@1 和 Precision@1 一样吗？** | **一样。** K=1 时"有没有"和"有几个÷1"是同一件事 |

最后一条解释了为什么报告里通常只写 `Recall@1`，不写 `Precision@1`。

---

## 11. 一句话总结

> **Recall@K：前 K 名里"有没有"对的 → 0 或 1 → 平均后就是"成功率"**
>
> **Precision@K：前 K 名里"有几个"对的 ÷ K → 比例 → 衡量候选列表干不干净**
>
> **VPR 重 Recall，因为几何验证只需要一个正确候选；precision 低只是多跑几次验证的算力成本。**
