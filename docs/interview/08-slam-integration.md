# M8 · 接进 SLAM 系统

> 本项目做的是回环检测的**第一级**（候选检索）。本章讲：完整流水线长什么样、你的模块接进去要改什么、
> 以及一个零训练就能 +38 个点的实验。

## 0. 开场：一个实验结果

用**完全没微调的 baseline 特征**，只在检索后加一步**序列匹配**（利用 query 是连续轨迹这个事实）：

| 方法 | night R@1 | R@5 | R@10 |
|---|---:|---:|---:|
| 单帧匹配（当前实现） | 0.510 | 0.740 | 0.870 |
| **序列匹配（窗口 ±5 帧）** | **0.890** | 0.900 | 0.910 |

**+38 个点。零训练。纯推理后处理。** 对比：triplet 微调在训练集上（train-on-test）才到 0.860。

**为什么效果这么好？** R@10 从 0.870 只升到 0.910，几乎没动；R@1 从 0.510 冲到 0.890。

> **序列匹配没有提升"找得到"的能力，它提升的是"排得准"的能力。**
>
> 而 M5/M7 的诊断正是：**"不是找不到，是排不准"**。

**因果闭环**：诊断问题在排序 → 序列约束正是修排序的手段 → 实测验证。这是整个项目最漂亮的论证链。（前提说明见 §8.3）

## 1. SLAM 系统整体结构

以 ORB-SLAM2 为模板，四条线程：

```
                    ┌─────────────────────────────────────────┐
   相机图像 ──────► │  ① 追踪 Tracking（前端）                │
                    │     提特征 → 与上一帧匹配 → 估计位姿     │
                    │     判断要不要设为【关键帧】             │
                    └──────────────┬──────────────────────────┘
                                   │ 新关键帧
                    ┌──────────────▼──────────────────────────┐
                    │  ② 局部建图 Local Mapping               │
                    │     三角化新地图点、局部 BA 优化         │
                    └──────────────┬──────────────────────────┘
                                   │ 关键帧入库
                    ┌──────────────▼──────────────────────────┐
                    │  ③ 回环检测 Loop Closing   ← 本项目在这  │
                    │     候选检索 → 几何验证 → 一致性检查     │
                    └──────────────┬──────────────────────────┘
                                   │ 确认的回环
                    ┌──────────────▼──────────────────────────┐
                    │  ④ 位姿图优化 + 全局 BA + 地图融合      │
                    └─────────────────────────────────────────┘
```

### 1.1 必须先懂：关键帧（keyframe）

**SLAM 不会把每帧都存进数据库。** 相机 30 FPS，站着不动 1 秒就是 30 张几乎一样的图。

只挑**关键帧**存，条件大致是：
- 距上一关键帧移动/转动足够多（视差够大）
- 追踪到的地图点降到一定比例（快跟丢了）
- 距上一关键帧过了足够多帧

> 📌 **对本模块的意义**：**database 就是关键帧库，且随机器人运行不断增长**——不是现在这样 100 张固定不变。这是接入的第一个改动点。

## 2. 回环检测的完整四步

```
当前关键帧
    │
    ▼
① 候选检索        ← 本项目：抽特征 → 检索 → Top-K
    │  输出：K 个可能的历史关键帧
    ▼
② 几何验证        ← 局部特征匹配 + RANSAC，检查内点数
    │  输出：通过/不通过 + 相对位姿 T
    ▼
③ 一致性检查      ← 要求连续多帧检测到一致的回环
    │  输出：确认/拒绝
    ▼
④ 位姿图优化      ← 加边 + 全局优化 + 地图点融合
```

**这是一个逐级收紧的漏斗**：第 ① 步宽松（要高 recall），后面越来越严（保证 precision）。这就是 M1 那个"为什么 VPR 重 recall"的结构性原因。

---

## 3. 本模块接进去要改四件事

| 改动 | 现在 | 接入后 |
|---|---|---|
| **① 增量数据库** | 100 张固定，一次算完存 `.pt` | **随关键帧增长**，需在线 `add()`。用 FAISS 或 HNSW（M4：HNSW 天然支持插入） |
| **② 时序排除** | 不需要（两次独立采集） | **必须排除最近 N 个关键帧**，否则检索到的全是"我刚刚经过这里"（M5 §9） |
| **③ 拒绝机制** | 永远返回 Top-K | **需要相似度阈值**——大部分时候机器人在新地方，正确答案是"没有回环" |
| **④ 实时性** | 离线批处理 | 每个关键帧跑一次，几 Hz。ResNet18 在 GPU 上几毫秒可以；嵌入式要考虑量化/TensorRT |

> 📌 **第 ③ 条最值得讲**。面试官容易问："你的系统怎么判断当前位置是个**新地方**？"
>
> 答案是：**现在判断不了**。`topk` 永远返回 K 个结果，哪怕全是错的。真实系统需要阈值或比值判据（如最高分/次高分比值，类似 SIFT 的 ratio test）。这也是 M1 说"算不了 Recall@100%Precision"的原因。

## 4. 几何验证 ⭐

面试官问"你怎么知道候选是对的"时的答案。

### 4.1 三个步骤

**① 提局部特征**

全局描述子告诉你"这两张图是同一个地方"，但**不告诉你哪个点对应哪个点**。几何验证需要点对点对应，所以要提局部特征：

- 传统：**ORB**（快，二值）、SIFT、SURF
- 学习型：**SuperPoint**、DISK、ALIKED

**② 特征匹配**

- 传统：暴力匹配 / FLANN + **ratio test**（Lowe 的 0.7~0.8 阈值）
- 学习型：**SuperGlue** / **LightGlue**（图神经网络做匹配，效果显著更好）

**③ 几何模型 + RANSAC**

匹配里必然混着错误配对。RANSAC 的作用是**在含噪声的对应中找出符合同一几何模型的子集**。

### 4.2 RANSAC 原理（必须能讲）

```
重复 N 次：
  1. 随机抽最少数量的点对（求基础矩阵需 8 对，PnP 需 3~4 对）
  2. 用这几对算出一个候选几何模型
  3. 拿它检验【所有】点对，统计有多少对符合（内点 inlier）
  4. 记下内点最多的模型

最后：内点数 > 阈值 → 接受回环；否则拒绝
```

**直觉**：正确匹配都服从**同一个**几何关系（来自同一个真实三维场景），错误匹配是随机散落的。所以"能让最多点对同时满足的模型"就是真的。

### 4.3 用哪个几何模型

| 情况 | 模型 | 说明 |
|---|---|---|
| **2D-2D**：只有两张图的像素点 | **本质矩阵 E / 基础矩阵 F** | 解出 R 和平移方向，但**平移尺度未知**（单目固有问题） |
| **3D-2D**：候选关键帧有地图点，当前帧有 2D 特征 | **PnP** | 解出完整 R 和 t。**回环检测最常用**，因为历史关键帧已三角化出地图点 |
| **3D-3D**：两边都有地图点 | **ICP / Sim(3)** | 单目还要估**尺度因子 s**（尺度漂移） |

**判据**：ORB-SLAM2 大致要求 RANSAC 后内点数 > 20，后续优化后 > 40，才接受回环。

## 5. 一致性检查

即使几何验证通过，ORB-SLAM2 **还要再加一层**：

> **连续 3 个关键帧都检测到"共视组一致"的回环候选，才真正接受。**

**逻辑**：单次误检可能是巧合（路过一个长得像的地方），但**连续三次误检到同一组关键帧，概率极低**。

代价是**延迟**（要等 3 个关键帧）。但相比错误回环撕裂地图的代价，完全值得。

> 📌 体现 SLAM 工程的核心态度：**宁可晚一点、漏一点，也绝不能错**。呼应 M1 的误检代价不对称。

## 6. 位姿图优化

### 6.1 优化的是什么

```
节点：每个关键帧的位姿
边：  里程计边（相邻关键帧，来自前端）+ 回环边（跨时间，来自本模块）
目标：找一组位姿，让所有边的误差平方和最小
```

求解器：**g2o**（ORB-SLAM）、**GTSAM**（因子图，Kimera）、**Ceres**（VINS-Fusion）。本质都是非线性最小二乘（高斯-牛顿 / LM）。

### 6.2 单目要用 Sim(3) 而非 SE(3) ⭐

- **SE(3)** = 旋转 + 平移，**6 自由度**
- **Sim(3)** = 旋转 + 平移 + **尺度**，**7 自由度**

单目 SLAM 没有绝对尺度，走久了会**尺度漂移**——回到原地时地图的"大小"已和当初不同。所以回环边必须携带尺度因子，用 Sim(3) 优化才能把尺度也校正回来。

（双目 / RGB-D / 带 IMU 的系统有绝对尺度，SE(3) 就够。）

> 好细节题。被问"单目 SLAM 的回环和双目有什么不同"，答 Sim(3) vs SE(3) 很到位。

### 6.3 优化完还要地图融合

位姿校正后，同一物理点在地图里可能有两份副本（第一次经过一份、这次一份）。需要**地图点融合（map point fusion）**合并，否则地图有重影。

## 7. 与 DBoW2 的对比 ⭐ 高频问题

| | **DBoW2** | **本项目（CNN 全局描述子）** |
|---|---|---|
| 特征 | ORB（手工，二值） | ResNet18 全局特征 |
| 表示 | 词袋直方图（稀疏、高维） | 512 维稠密向量 |
| 匹配 | TF-IDF 加权 + **倒排索引** | 余弦相似度 + topk |
| 训练 | 离线聚类词汇树，**无监督** | 需标注数据微调 |
| 增量插入 | **天然支持** | 需 ANN 索引配合 |
| 速度 | **极快**，纯 CPU，毫秒级 | 需 GPU 推理 |
| 光照鲁棒性 | **差** | **好** |
| 视角鲁棒性 | 中等 | 好 |
| 工程成熟度 | **ORB-SLAM 实战验证多年** | 研究阶段居多 |

### 7.1 最关键的一条优势不在表里 ⭐

> **DBoW2 用的 ORB 特征，和几何验证用的 ORB 特征是同一批。**

前端追踪时已经提了 ORB → 拿来建词袋做检索 → 检索完**直接拿这批特征做几何验证**。**整条链只提一次特征，零额外成本。**

而本方案：CNN 提全局特征做检索 → **还得再提一次局部特征**才能做几何验证。**多一份计算开销。**

> 📌 **非常实在的工程论点**。能说出这条，说明你理解的是**系统**而不只是**模块**。
>
> **标准答法**：「学习型描述子在光照剧变下明显更强，我实测昼夜场景 DBoW2 类方法会很吃力。但 DBoW2 有个系统级优势——它和几何验证共用同一套 ORB 特征，整条链只提一次；我的方案要额外再提一次局部特征。所以实际选型看场景：主要挑战是昼夜/季节变化，学习型值得这个开销；光照稳定的室内，DBoW2 性价比更高。」

## 8. 序列匹配（SeqSLAM）

### 8.1 核心思想

单帧匹配把每帧当**独立**事件，但机器人是**连续运动**的，这个约束被白白扔掉了。

**假设**：

> 如果 query 第 t 帧匹配 database 第 j 帧，
> 那么 query 第 t+1 帧应该匹配 database 第 j+1 帧。

所以不看单个相似度，看**相似度矩阵上的一条轨迹**：

```
        database →
   q   ┌──────────────────┐
   u   │  ·  ·  ╲  ·  ·   │   ← 正确匹配沿对角线形成【连续高分带】
   e   │  ·  ·  ·╲ ·  ·   │
   r   │  ·  ·  ·  ╲ ·    │      误匹配是孤立亮点
   y   │  ·  ·  ·  · ╲    │
   ↓   └──────────────────┘
```

**SeqSLAM**（Milford & Wyeth, ICRA 2012）在这个矩阵上搜索最佳直线轨迹，并在多个"速度"（斜率）上搜索。

### 8.2 实测（简化版：沿对角线做窗口平均）

**非因果版**（用前后帧，适合离线/批处理）：

| 窗口 | night R@1 | night R@5 | night R@10 | day R@1 |
|---|---:|---:|---:|---:|
| 单帧（基线） | 0.510 | 0.740 | 0.870 | 0.960 |
| ±1（3 帧） | 0.490 | 0.850 | 0.910 | 0.960 |
| ±2（5 帧） | 0.560 | 0.860 | 0.920 | 0.960 |
| ±3（7 帧） | 0.720 | 0.870 | 0.930 | 0.970 |
| **±5（11 帧）** | **0.890** | 0.900 | 0.910 | **0.990** |

**因果版**（只用过去帧，**在线 SLAM 的真实条件**）：

| 窗口 | night R@1 | night R@5 |
|---|---:|---:|
| 单帧 | 0.510 | 0.740 |
| 过去 5 帧 | 0.620 | 0.860 |
| 过去 10 帧 | 0.760 | 0.880 |
| **过去 15 帧** | **0.780** | 0.860 |

**在线可用的条件下仍有 +27 个点。**

### 8.3 ⚠️ 必须说清的三个前提

**① 简化版假设"速度比 = 1"** —— 两次采集的行进速度完全一致，query 第 t 帧正好对应 database 第 j+t 帧。Gardens Point 恰好满足（同一路线步行采集）。**真实 SeqSLAM 要在多个速度上搜索**。

**② 需要连续轨迹** —— query 若是随机单张图（如从图片库定位），完全用不了。

**③ 引入延迟** —— 因果版需"已走过 15 帧"才有完整窗口。机器人原地转向、倒着走、走岔路时，序列假设会失效。

### 8.3b v2 已实装，held-out 上的结果

序列匹配已实现为 `src/sequence_match.py`，在**严格 held-out 段 070-099** 上：

| 配置 | R@1 | P@5 | R@100%P |
|---|---:|---:|---:|
| v2 单帧 | 0.633 | 0.607 | 0.033 |
| **+ 序列匹配（因果，在线条件）** | **1.000** | 0.893 | **1.000** |

⚠️ **两个必须一起说的对照**：

- **baseline 特征 + 同样的序列匹配也能到 1.000** → 这个 100% 主要是**序列匹配**的功劳，不是训练的功劳
- **打乱 query 时序后降到 0.300** → 证明增益确实来自时序约束，不是实现假象

以及那个 100% 的前提：Gardens Point 逐帧对齐、速度稳定，完美满足序列假设。真实场景增益会小得多。

完整消融见 [`docs/experiments.md`](../experiments.md)。

### 8.4 为什么这个实验值得放进简历

它构成了一条完整的**科学论证链**：

```
观察：R@1=0.51 但 R@10=0.87
  ↓
诊断：不是找不到，是排不准（M5）
  ↓
特征空间验证：类内/类间相似度差距只有 0.081，是白天的一半（M2）
  ↓
假设：引入时序约束辅助排序，应能大幅改善 R@1 而不太动 R@10
  ↓
实验：R@1 0.510→0.890（+38），R@10 0.870→0.910（+4）
  ↓
结论：假设成立，且零训练成本
```

> **这比"我微调了一下涨了几个点"有价值得多**——展示的是**发现问题 → 归因 → 提出假设 → 验证**的完整方法论。

## 9. 这个模块要"上车"还差什么

| 缺口 | 说明 |
|---|---|
| **增量索引** | 换 FAISS/HNSW，支持在线 `add()` |
| **时序排除** | 排除最近 N 个关键帧 |
| **拒绝机制** | 相似度阈值或 ratio test，能输出"这是新地方" |
| **几何验证** | 完全没有。从"检索模块"到"回环检测模块"的必经一步 |
| **一致性检查** | 连续多帧确认 |
| **与位姿图对接** | 输出相对位姿 T（含 Sim(3) 的尺度） |
| **实时性验证** | 嵌入式平台的延迟/内存实测 |
| **跨环境泛化验证** | 只在一个校园数据集验证过，换环境要重测 |

> 被问"这个能直接用在真实机器人上吗"——**诚实答案是"不能，它现在是回环检测的第一级"**，然后照表说缺什么。**准确说出自己模块的边界，比夸大能力可信得多。**

## 10. 面试怎么答

### Q1：你的模块在 SLAM 系统里处于什么位置？

> 回环检测的第一级，也就是候选检索。完整的回环检测是四步：候选检索给出 Top-K 个可能的历史关键帧，几何验证用局部特征匹配加 RANSAC 确认，一致性检查要求连续多帧都检测到同一回环，最后才把这条边加进位姿图做优化。我做的是第一步。
>
> 这是个逐级收紧的漏斗——第一步要宽松、追求高召回，后面越来越严来保证精度。这也是为什么 VPR 的主指标是 Recall@K。

### Q2 ⭐：你怎么知道检索出来的候选是对的？

> 光靠全局描述子的相似度是不够的，必须做几何验证。步骤是：先提局部特征，传统用 ORB 或 SIFT，学习型用 SuperPoint；然后做描述子匹配，传统用 FLANN 加 ratio test，学习型用 SuperGlue 或 LightGlue；最后用 RANSAC 估几何模型。
>
> RANSAC 的逻辑是随机抽最小点集算一个候选模型，拿它去检验所有匹配统计内点数，重复多次取内点最多的。因为正确的匹配都服从同一个几何关系——它们来自同一个真实三维场景——而错误匹配是随机散落的。最后看内点数超不超过阈值，ORB-SLAM2 大概要求 20 以上。
>
> 用什么模型取决于有什么数据：只有两张图的 2D 点就用本质矩阵，但单目解不出平移尺度；如果候选关键帧已经有三角化的地图点，就用 PnP，能解出完整位姿，回环检测里这个最常用。

### Q3 ⭐：和 ORB-SLAM 的 DBoW2 相比，你的方案好在哪差在哪？

（见 §7.1 的标准答法，重点是那条"共用 ORB 特征"的系统级论点）

### Q4：单目 SLAM 的回环优化有什么特别的？

> 要用 Sim(3) 而不是 SE(3)。单目没有绝对尺度，走久了会尺度漂移，回到原地时地图的大小已经和当初不一样了。SE(3) 只有旋转和平移六个自由度，Sim(3) 多一个尺度因子，七个自由度，这样优化时才能把尺度也校正回来。双目、RGB-D 或者带 IMU 的系统有绝对尺度，用 SE(3) 就够。
>
> 另外位姿优化完还没结束，同一个物理点可能在地图里有两份副本，还要做地图点融合，否则地图会有重影。

### Q5 ⭐：你的系统怎么判断当前是个新地方（没有回环）？

> 现在判断不了，这是个明确的缺口。`topk` 永远返回 K 个结果，哪怕全是错的。真实系统需要一个拒绝机制——设相似度阈值，或者用最高分和次高分的比值做判据，类似 SIFT 匹配里的 ratio test。而且在真实场景里，机器人绝大多数时候都在新地方，"没有回环"才是常态。
>
> 这也是为什么我算不了 Recall@100%Precision 这个 SLAM 里更关心的指标——它需要一个可以扫描的拒绝阈值。

### Q6 ⭐：如果继续做，怎么提升 R@1？

> 我已经验证了一个方向：序列匹配。单帧匹配把每一帧当独立事件，但机器人是连续运动的，如果 query 第 t 帧匹配 database 第 j 帧，那第 t+1 帧应该匹配第 j+1 帧。我在相似度矩阵上沿对角线做窗口平均，用完全没微调的 baseline 特征，night_right 的 R@1 从 0.510 涨到 0.890，加了 38 个点，零训练成本。只用过去帧的因果版本——也就是在线 SLAM 的真实条件——也有 0.780，加 27 个点。
>
> 有意思的是 R@10 几乎没动，从 0.870 到 0.910。**说明序列约束提升的不是"找得到"，而是"排得准"**，正好对上我之前的诊断。
>
> 前提要说清楚：我这个简化版假设两次采集速度一致，真实 SeqSLAM 要在多个速度上搜索；而且需要连续轨迹，机器人原地转向或走岔路时会失效。

### Q7：这个能直接用在真实机器人上吗？

> 不能，它现在只是回环检测的第一级。缺的东西很明确：数据库要换成支持在线插入的 FAISS 或 HNSW，因为关键帧是不断增长的；要加时序排除，否则检索到的全是刚刚经过的地方；要加拒绝机制来判断新地方；最关键的是完全没有几何验证，而那是从"检索模块"变成"回环检测模块"的必经一步。另外还要输出相对位姿给位姿图，以及在嵌入式平台上实测延迟和内存。
