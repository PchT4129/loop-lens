# 附录 N · 微调（Fine-tuning）

> 项目无关的通用主题。**CV 时代的微调**和 **LLM 时代的微调**基本是两套东西，本章都讲。
> 前置：A1（优化器/学习率）、A3（正则化）、A7（BatchNorm）、A8（残差的"默认值"哲学）。

---

## 1. 微调为什么有效

**本质是迁移学习**：预训练模型已学会通用的东西，你只需在其基础上做**小幅调整**适配新任务。

**为什么通用的东西可复用**：任务共享大量底层结构。

- CV：边缘、纹理、形状——**任何视觉任务都需要**（A6 §6 第一层 kernel 学的就是这些）
- NLP：语法、词义、常识——**任何语言任务都需要**

所以微调改的**主要是高层、任务特定的部分**，底层基本不用动。

> 📌 **微调 = 借用别人在海量数据上学到的表征，只花很小代价适配到小数据上。**
>
> A3 那句"预训练本身就是最强的正则化"说的就是这件事——它相当于给小数据集**免费注入了海量样本的信息**。

## 2. CV 时代的微调策略

### 2.1 冻结多少层？（ResNet18 实测）

```
策略                      | 可训练参数    | 占比
全部可训练                  | 11,689,512  | 100.00%
冻结 conv1+layer1          | 11,532,008  |  98.65%
只训 layer3+layer4         | 11,006,440  |  94.16%
只训 layer4                |  8,906,728  |  76.19%
只训最后的 fc（线性探测）      |    513,000  |   4.39%
```

> ⚠️ **反直觉点**：冻结 `conv1+layer1` 只减少 **1.35%** 参数量。
>
> **CNN 的参数量绝大部分集中在深层**（通道数多），`layer4` 一层占 76%。
>
> **所以"冻结浅层"省的不是显存，而是限制模型自由度——它是正则化手段（A3 的 A 类），不是省算力的手段。** 这个区分要说清楚。

### 2.2 三种典型策略

| 策略 | 做法 | 什么时候用 |
|---|---|---|
| **线性探测 linear probing** | 冻结全部 backbone，只训分类头 | 数据极少；或只想**评估表征质量** |
| **部分微调** | 冻结浅层，训深层 | **数据较少**时的主流选择 |
| **全参微调** | 全部可训练 | 数据充足，或目标域与预训练域差异大 |

### 2.3 分层学习率（layer-wise lr decay）

比"冻结/不冻结"更精细：**越浅的层用越小的学习率。**

```
lr_layer_k = base_lr × decay^(总层数 − k)      # decay 通常 0.65~0.9
```

**直觉**：浅层学通用特征只需微调，深层要适配新任务可以大改。**这是"冻结"的连续版本**（冻结相当于 lr=0）。BERT、ViT 的微调里是标配。

### 2.4 其他要点

- **学习率要小**（1e-5 ~ 1e-4）——A1 §7，大学习率破坏预训练权重，叫**灾难性遗忘**
- **warmup 很重要**——新加的分类头是随机初始化的，初期梯度很大会冲坏 backbone
- **BatchNorm 常冻结**——A7 §7.1，小 batch 统计量不可靠，不如信任预训练的 running stats

## 3. LLM 时代：为什么全参微调不可行

**显存是硬约束。** 7B 模型的账（实算）：

```
项目                        | 全参微调    | LoRA (r=8)
模型权重 (FP16)              | 14.0 GB   | 14.00 GB
梯度 (FP16)                 | 14.0 GB   |  0.01 GB
Adam 优化器状态 (m+v, FP32)   | 56.0 GB   |  0.03 GB
参数副本 (FP32 master)       | 28.0 GB   |  0.02 GB
─────────────────────────────────────────────────
合计（不含激活）              | 112.0 GB  | 14.06 GB
```

**两个要点：**

**① 优化器状态是最大头（56 GB），不是模型本身。** Adam 要为每个参数存 **m 和 v**（A1 §6.4 讲的那两个量），通常用 FP32 以保证数值稳定。**现在你知道它们在工程上有多贵了。**

**② 全参微调 7B 要 112 GB，单卡放不下**（H100 是 80GB）。

**这就是 PEFT（Parameter-Efficient Fine-Tuning）存在的全部理由。**

## 4. LoRA ⭐

### 4.1 原理

**假设**：微调带来的权重变化 `ΔW` 是**低秩**的，可分解成两个小矩阵的乘积。

```
原来:  h = Wx                    W 是 [d × k]，冻结不动
LoRA:  h = Wx + BAx              B 是 [d × r]，A 是 [r × k]，r << min(d,k)
```

**只训练 A 和 B，`W` 完全冻结。**

### 4.2 能省多少（实算）

```
层规模 d × k        | 全量参数      | LoRA r=8   | 压缩比
512 × 512          | 262,144     | 8,192      | 32 ×
768 × 768          | 589,824     | 12,288     | 48 ×
4096 × 4096        | 16,777,216  | 65,536     | 256 ×
4096 × 11008       | 45,088,768  | 120,832    | 373 ×
```

**层越大省越多**——全量是 `d×k`（二次），LoRA 是 `r×(d+k)`（一次）。

### 4.3 一个漂亮的设计细节 ⭐

**`B` 初始化为全 0，`A` 随机初始化。** 于是训练开始时 `BA = 0`，**模型输出与原模型完全一致**。

> 📌 **保证微调从预训练模型"平滑出发"**，不会一上来就被随机初始化的旁路搞坏。
>
> 这和 A8 讲的残差连接是**同一个哲学**：**把"什么都不做"设为默认值，让模型在此基础上学增量。**

### 4.4 ⚠️ 低秩假设：我实测了一个负面结果

拿本项目真实微调前后的 ResNet18 权重做差，对 `ΔW` 做 SVD：

```
层                | 矩阵形状     | 前8个奇异值占能量 | 有效秩(覆盖90%能量)
layer1.0.conv1   | 64×576     | 65.2%          | 30 / 64
layer2.0.conv1   | 128×576    | 41.8%          | 68 / 128
layer3.0.conv1   | 256×1152   | 26.4%          | 153 / 256
layer4.0.conv1   | 512×2304   | 20.6%          | 304 / 512
layer4.1.conv2   | 512×4608   | 44.2%          | 222 / 512
```

**`ΔW` 一点都不低秩**——覆盖 90% 能量需要 304/512 的秩，前 8 个奇异值只占 20%。

**为什么和 LoRA 论文不一致？** 三个原因：

1. **模型规模差太远**。低秩现象是在 **GPT-3 175B** 这类超大模型上观察到的。**参数越多冗余越大**，真正需要改动的"本征维度"越低。ResNet18 只有 1100 万参数，本来就没多少冗余。
2. **层类型不同**。LoRA 主要作用在 **Transformer 的注意力投影矩阵**（`W_q, W_v`），那是真正的方阵。这里把卷积核 reshape 成 2D，结构完全不同。
3. **训练方式不同**。全参 AdamW 会让**每个权重都动一点**，加上 weight decay，`ΔW` 更像弥散在所有方向的扰动，而非集中在几个主方向。

> 📌 **诚实结论**：
>
> **"微调的权重变化是低秩的"不是普适定律，而是在【大模型 + Transformer + 下游任务】这个特定组合下的经验观察。**
>
> 我在小 CNN 上实测它不成立。而这恰好解释了**为什么 LoRA 是 LLM 时代的产物，不是 CV 时代的**。

**面试时能说出"我验证过它在什么情况下不成立"，比背"LoRA 有效"段位高得多。**

### 4.5 PEFT 家族

| 方法 | 做法 | 特点 |
|---|---|---|
| **LoRA** | 加低秩旁路 | **主流**。推理时可把 `BA` **合并进 W**，零额外延迟 |
| **QLoRA** | 基模型 **4bit 量化** + LoRA | 显存再降，24GB 卡能微调 33B |
| **Adapter** | 层间插入小 MLP 瓶颈层 | 早期方法。**推理无法合并，有额外延迟** |
| **Prefix / Prompt Tuning** | 输入前拼可学习的虚拟 token | 参数最少，效果和稳定性一般 |
| **(IA)³** | 学缩放向量调制激活 | 参数极少 |

> **LoRA 胜出的关键是「可合并」**：推理时 `W' = W + BA` 算好存下，**推理开销和原模型完全相同**。Adapter 做不到。

## 5. LLM 微调的下游形态

```
预训练 (Pretraining)          海量文本，学"下一个词"
    ↓
SFT (监督微调)                指令-回答对，学"怎么听指令"
    ↓
对齐 (Alignment)             学"什么样的回答更好"
    ├─ RLHF: 训练奖励模型 + PPO 强化学习   （复杂、不稳定）
    └─ DPO:  直接用偏好对优化，跳过奖励模型  （简单、现在主流）
```

**DPO 相比 RLHF 的核心简化**：RLHF 要先训奖励模型再用 PPO 优化，两阶段、超参多、易崩。**DPO 数学上证明可以把两步合并成一个直接的分类式损失**，用偏好对（"A 比 B 好"）直接训。

> 💡 **DPO 的损失形式和 B3 的对比学习很像**——都是"让好的比坏的分数高"。这类"从相对偏好中学习"的思路是相通的。

## 6. 什么时候【不该】微调 ⭐ 最实用的一条

```
需求来了
   │
   ├─ 只是"输出格式/风格"不对？        → 改 prompt，别微调
   │
   ├─ 模型"不知道"某些事实/知识？       → 用 RAG，别微调
   │
   ├─ 只有几十条样本？                → few-shot prompt，别微调
   │
   └─ 需要模型掌握"新能力/新行为"，
      且有几千条以上高质量数据          → 才考虑微调
```

**三条判断原则：**

**① 微调教的是"行为/风格/能力"，不是"知识"。** 想让模型知道公司内部文档 → **用 RAG**。微调塞知识效率极低，且易产生幻觉（学会了语气，记不住事实）。

**② 先穷尽 prompt engineering。** 很多"需要微调"的需求，改 system prompt 加几个 few-shot 例子就解决了。**微调的成本（数据+算力+维护+版本管理）远高于写 prompt。**

**③ 数据质量 >> 数据数量。** LIMA 论文的结论：**1000 条高质量数据的效果超过 5 万条噪声数据。** 微调最大的风险不是数据不够，是**数据有毒**——模型会忠实学会你数据里的坏习惯。

## 7. 常见坑

| 坑 | 表现 | 怎么防 |
|---|---|---|
| **灾难性遗忘** | 新任务好了但**原有能力退化** | 小学习率、LoRA（不动原权重）、混入通用数据 |
| **过拟合** | 训练集完美，泛化崩 | A3 那一整套 |
| **数据泄漏** | 指标虚高 | A3 §5，按相关性分组切分 |
| **只看 loss** | loss 降了但实际变差 | **必须有独立评测**——本项目那个 `loss 0.002 而 R@1 掉到 0.30` 就是活例子 |
| **数据质量问题** | 学会标注者的坏习惯 | 人工抽检，宁缺毋滥 |

## 8. 面试怎么答

### Q1：微调时你会冻结哪些层？为什么？

> 取决于数据量。数据极少就做线性探测，只训分类头；数据较少冻结浅层训深层；数据充足或域差异大就全参微调。更精细的做法是分层学习率，越浅的层学习率越小，本质上是"冻结"的连续版本。
>
> 有一点要说清楚：**冻结浅层省的不是显存**。我算过 ResNet18 冻结 conv1 加 layer1 只减少 1.35% 的参数，因为 CNN 参数绝大部分集中在深层，layer4 一层就占 76%。**所以冻结浅层是正则化手段，目的是限制模型自由度，不是为了省算力。**

### Q2 ⭐：LoRA 的原理是什么？为什么它能省这么多？

> 它假设微调带来的权重变化 ΔW 是低秩的，所以冻结原权重 W，只训练两个小矩阵 B 和 A，前向变成 `h = Wx + BAx`。省的原因是全量参数是 d×k 的二次量，LoRA 是 r×(d+k) 的一次量——4096×11008 的层用 r=8 能省 373 倍。
>
> 显存上更夸张。7B 全参微调需要约 112 GB，其中最大头不是模型的 14 GB，而是 Adam 优化器状态的 56 GB——它要为每个参数存一阶矩和二阶矩，还是 FP32。LoRA 因为可训练参数只有 0.06%，优化器状态几乎不占，总共约 14 GB，一张 4090 就够。
>
> 还有个设计细节我觉得很漂亮：**B 初始化为全 0**，所以训练起点 BA=0，模型输出和原模型完全一致，保证微调是从预训练模型平滑出发的。这和残差连接"把恒等映射设为默认值"是同一个哲学。

### Q3 ⭐：LoRA 的低秩假设一定成立吗？

> 不一定，我实测过一个反例。我拿一个 ResNet18 微调前后的权重做差，对 ΔW 做 SVD，发现覆盖 90% 能量需要 304/512 的秩，前 8 个奇异值只占 20% 的能量——**完全不低秩**。
>
> 原因我分析有三个：一是模型规模，低秩现象是在 GPT-3 这种超大模型上观察到的，参数越多冗余越大、本征维度越低，而 ResNet18 只有 1100 万参数本来就没多少冗余；二是层类型，LoRA 主要用在 Transformer 的注意力投影矩阵上，和卷积核 reshape 出来的矩阵结构不同；三是全参 AdamW 加 weight decay 会让每个权重都动一点，ΔW 更像弥散的扰动。
>
> 所以我的理解是：**低秩不是普适定律，是"大模型+Transformer+下游任务"这个特定组合下的经验观察**。这也解释了为什么 LoRA 是 LLM 时代的产物而不是 CV 时代的。

### Q4 ⭐：什么情况下不该用微调？

> 三种情况。第一，如果只是输出格式或风格不对，改 prompt 就够了，微调的综合成本高得多。第二，如果模型是"不知道某些事实"，应该用 RAG——**微调教的是行为和风格，不是知识**，硬塞知识效率低还容易产生幻觉。第三，样本只有几十条的话 few-shot prompt 更合适。
>
> 真正该微调的场景是：需要模型掌握一种新的行为模式或能力，而且有几千条以上的高质量数据。这里数据质量比数量重要得多，LIMA 那篇论文的结论是 1000 条高质量数据能超过 5 万条噪声数据。

### Q5：RLHF 和 DPO 的区别？

> RLHF 是两阶段：先用人类偏好数据训一个奖励模型，再用 PPO 做强化学习去优化策略。问题是流程复杂、超参多、训练不稳定。DPO 从数学上证明了这两步可以合并——直接用偏好对构造一个分类式的损失函数去优化，跳过奖励模型和强化学习。简单很多，现在是主流。思路上它和对比学习很像，都是"让好的比坏的分数高"。

## 9. 小结

| 要点 | 内容 |
|---|---|
| **微调为什么有效** | 底层表征通用可复用；**相当于给小数据免费注入海量信息** |
| **CV 冻结的反直觉** ⭐ | 冻结 conv1+layer1 只省 **1.35%** 参数。**冻结是正则化，不是省算力** |
| **分层学习率** | 越浅 lr 越小，"冻结"的连续版本 |
| **显存账** ⭐ | 7B 全参 **112 GB**，**优化器状态 56 GB 是最大头** |
| **LoRA** | `h = Wx + BAx`，4096×11008 省 **373 倍** |
| **B 初始化为 0** ⭐ | 起点输出与原模型一致——和残差"默认恒等"同一哲学 |
| **低秩假设** ⭐ | **实测小 CNN 上不成立**（有效秩 304/512）。是大模型+Transformer 的经验观察，非普适定律 |
| **LoRA 为何胜出** | **可合并进 W，零额外推理延迟** |
| **SFT/DPO/RLHF** | **DPO 把 RLHF 两阶段合成一步** |
| **不该微调的情况** ⭐ | 格式→prompt；**知识→RAG**；样本少→few-shot。**微调教行为不教知识** |
| **数据质量** | **1000 条高质量 > 5 万条噪声**（LIMA） |
