# 附录 K · 对比学习与 InfoNCE（第二梯队 B3）

> 与本项目关系最直接的一章——**InfoNCE 基本取代了 triplet loss**，是"如果现在重做这个项目会怎么做"的标准答案。
> 前置：M6（triplet）、M7 §3（24% 零梯度）、A9（softmax 与交叉熵）。

---

## 1. 先回顾 triplet loss 的三个病

InfoNCE 恰好一次治好全部三个：

| 病 | 表现 |
|---|---|
| **① 大量样本零梯度** | 实测 **24%** 的三元组 loss 已是 0，训练空转 |
| **② 需要显式挖掘难样本** | 要自己写 semi-hard / batch-hard，还容易挑到噪声导致训练崩 |
| **③ 信息利用率极低** | **一步只用 1 个负样本**，其余全浪费 |

---

## 2. 核心想法：把度量学习变成分类

**Triplet 问的是判断题**："anchor 离 positive 是不是比离 negative 更近（至少 margin）？"

**InfoNCE 问的是选择题**：

> **给你 1 个正样本和 N 个负样本，共 N+1 个候选。哪一个才是 anchor 的正样本？**

```
        L = −log  ────────── exp(sim(a, p) / τ) ──────────
                  exp(sim(a,p)/τ) + Σᵢ exp(sim(a,nᵢ)/τ)
```

---

## 3. ⭐ 这个式子你已经学过了

分子是一项，分母是全部项的和，外面套 `−log`——**这就是 A9 的 softmax + 交叉熵。**

```
把相似度除以 τ 当作 logits，正样本当作"第 0 类"，做交叉熵。
```

实测验证：

```
相似度: 正=0.80  负=[0.75, 0.60, 0.30, 0.10]   τ=0.1

手写 −log(softmax(logits)[0]) = 0.559339
F.cross_entropy(logits, 0)    = 0.559339      ← 完全一致
```

> 📌 **InfoNCE = 把交叉熵用在了度量学习上。**
>
> "类别"不是固定的猫狗鸟，而是**这个 batch 里的候选样本**。所以它同时具备分类的优点（永远有梯度）和度量学习的优点（学相对距离、类别数不固定）。

---

## 4. ⭐ 自带难负样本挖掘（本章最重要）

A9 的梯度公式 `∂L/∂z = p − y` 代入这里：**每个负样本收到的梯度恰好等于它的 softmax 概率。**

实测（τ=0.1）：

```
样本      | 相似度  | softmax概率 | 梯度
正样本    | 0.80   | 0.5716     | −0.4284
负样本1   | 0.75   | 0.3467     | +0.3467    ← 最难
负样本2   | 0.60   | 0.0774     | +0.0774
负样本3   | 0.30   | 0.0039     | +0.0039
负样本4   | 0.10   | 0.0005     | +0.0005    ← 最易
```

**难负样本 0.3467 vs 易负样本 0.0005 —— 相差 665 倍。**

> 📌 **难样本挖掘是 softmax 自动做的，不需要写任何挖掘逻辑。**
>
> 为什么？A9 讲过 **`exp` 放大差距**。相似度越高的负样本在分母里占比越大，分到的梯度就越大。**"难"被自动量化成了权重。**

**直接治好病 ① 和病 ②**：

- 不再有零梯度——softmax 输出永远为正，**每个样本都贡献梯度**
- 不再需要手写挖掘——**难度加权内置**，且是**连续加权**而非"挑或不挑"的二元决策

---

## 5. 温度 τ：难样本聚焦旋钮

τ 是 InfoNCE 唯一的关键超参（取代 triplet 的 margin）。实测：

```
τ       | 各负样本的梯度权重 (相似度 0.75/0.60/0.30/0.10) | 最难/最易
0.02    | 0.0759  0.0000  0.0000  0.0000                | 758 亿倍
0.05    | 0.2654  0.0132  0.0000  0.0000                | 44 万倍
0.1     | 0.3467  0.0774  0.0039  0.0005                | 665 倍
0.5     | 0.2837  0.2102  0.1153  0.0773                | 3.7 倍
1.0     | 0.2456  0.2114  0.1566  0.1282                | 1.9 倍
10.0    | 0.2048  0.2017  0.1958  0.1919                | 1.1 倍
```

> - **τ 小** → 分布尖锐 → **几乎只盯最难的负样本**（τ=0.02 时差 758 亿倍，退化成 hardest mining）
> - **τ 大** → 分布平滑 → **所有负样本一视同仁**（τ=10 时只差 1.1 倍）

**τ 扮演的正是 triplet 里需要手工实现的"挖掘策略"**，只不过是连续旋钮而非离散算法选择。

**实践取值**：SimCLR 用 0.1，MoCo 用 0.07，CLIP 设成**可学习参数**。

> ⚠️ **τ 太小的风险和"无脑挑最难负样本"相同**（M6 §9）：死盯可能是标注噪声或本就该相似的样本，训练不稳。不是越小越好。

## 6. 为什么叫 "InfoNCE"

| 部分 | 含义 |
|---|---|
| **NCE** | Noise Contrastive Estimation——"把真实样本和噪声样本区分开"的经典思路 |
| **Info** | 它是 anchor 与 positive 之间**互信息 `I(a;p)` 的下界** |

（CPC 论文，van den Oord et al., 2018）：

```
I(a; p) ≥ log(N) − L_InfoNCE
```

**最小化 InfoNCE loss ⟺ 最大化互信息下界。**

注意 `log(N)`——**负样本越多，界越紧**。这从理论上解释了对比学习为什么需要大 batch。

> 被问"InfoNCE 名字什么意思"，答"它是互信息的变分下界，最小化它等于最大化正样本对的互信息，而且负样本数 N 决定界的紧度"，就说明不只是会用。

---

## 7. 谱系

| 方法 | 关键点 |
|---|---|
| **SimCLR** (2020) | 同图两次增强互为正样本，**batch 内其他所有图为负样本**。需 **batch=8192** |
| **MoCo** (2020) | **队列（queue）** 存历史特征当负样本 + **momentum encoder** 保一致性。**小 batch 也能有几万负样本** |
| **BYOL / SimSiam** | **完全不用负样本**（靠 predictor + stop-gradient 防塌缩）。反直觉但有效 |
| **CLIP** (2021) | 图文对比：N 图 × N 文，对角线为正样本。**τ 可学习** |

> **好记的对立点**：**SimCLR 用大 batch 换负样本数量，MoCo 用队列换负样本数量。**

## 8. 回到本项目：如果现在重做 ⭐

### 8.1 实测对比（用本项目真实特征）

```
Triplet (每个 anchor 随机 1 个负样本):
  平均 loss         : 0.0954
  loss==0 的三元组  : 24 / 100 = 24%      ← 完全不产生梯度
  每步用到的负样本数 : 1

InfoNCE (每个 anchor 用上全部 ~80 个负样本, τ=0.07):
  loss==0 的样本    : 0 / 100 = 0%        ← softmax 永远有梯度
  平均有效负样本数   : 38.7 (梯度权重>1%)
```

> **InfoNCE 一步用掉约 39 倍的负样本信息，且没有一个 anchor 白跑。**

⚠️ 两者 loss 数值（0.0954 vs 3.3478）**不可直接比较**——量纲不同（距离差 vs 交叉熵）。**能比的是"零梯度比例"和"有效负样本数"。**

### 8.2 代码怎么改

```python
# 现在（triplet）
loss = criterion(anchor_feat, positive_feat, negative_feat)   # 每个 anchor 1 个负样本

# 改成 InfoNCE
sim = anchor_feat @ positive_feat.T / tau        # [B, B] 相似度矩阵
labels = torch.arange(B, device=sim.device)      # 对角线是正样本
loss = F.cross_entropy(sim, labels)              # 就这一行
```

**每个 anchor 自动把 batch 内其他 B−1 个 positive 当负样本。三行，比 triplet 还简单。**

### 8.3 ⚠️ 但有两件事不能省

**① `negative_gap` 灰色地带的设计依然需要**（M6 §7.1）。

batch 内随机配对可能抽到帧号差只有 5 的两个样本——物理上很近、看起来很像，却被当负样本推开。**这个矛盾信号在 InfoNCE 里同样存在，而且因为难样本权重大，反而会被放大**（那正是相似度最高的负样本）。

**修法**：构造 mask，把帧号差在灰色地带的位置从分母里排除。

**② batch=16 太小。**

InfoNCE 效果强烈依赖负样本数量（`log(N)` 的界）。batch=16 只有 15 个负样本，远少于 SimCLR 的 8191。

**修法**：像 MoCo 维护特征队列；或利用本数据集小的特点，**直接把整个 database（100 张）当负样本池全量计算**。

## 9. 诚实的补充：InfoNCE 不是万能的

| 场景 | 更适合 |
|---|---|
| 大规模自监督预训练 | **InfoNCE**（负样本充足，无需标注） |
| 有明确三元组标注、负样本获取成本高 | **triplet** 仍可用 |
| 需要精确控制"多近算近" | **triplet 的 margin 是显式的**，τ 更间接 |
| 人脸识别这类超大类别数 | **margin-based softmax**（ArcFace/CosFace，A9 §8.3） |

**现在的主流格局**：自监督预训练用 InfoNCE，有标签的度量学习用 margin-based softmax，triplet 更多作为 baseline 或特定场景使用。

## 10. 面试怎么答

### Q1 ⭐：InfoNCE 和 triplet loss 的区别？

> Triplet 是判断题——anchor 离 positive 是不是比离 negative 更近至少一个 margin。InfoNCE 是选择题——给 1 个正样本和 N 个负样本，从 N+1 个候选里挑出正样本，本质就是 softmax 加交叉熵，把相似度除以温度当 logits、正样本当第 0 类。
>
> 最大的差别是 **InfoNCE 自带难样本挖掘**。它每个负样本收到的梯度恰好等于该样本的 softmax 概率，相似度越高权重越大。我实测过，相似度 0.75 的难负样本和 0.10 的易负样本，梯度差 665 倍。这把我本来要手写的 semi-hard mining 内置了，而且是连续加权不是二元挑选。
>
> 另外 triplet 满足 margin 后 loss 归零、不产生梯度——我在自己项目上实测有 24% 的三元组是这种情况；而 softmax 永远有梯度，零浪费。

### Q2 ⭐：温度 τ 起什么作用？

> 它是"难样本聚焦程度"的旋钮。τ 越小 softmax 分布越尖锐，梯度几乎全给最难的那个负样本——我测过 τ=0.02 时最难和最易负样本的梯度差 758 亿倍，基本退化成 hardest negative mining；τ 越大分布越平滑，τ=10 时权重只差 1.1 倍，等于一视同仁。
>
> 所以 τ 扮演的正是 triplet 里需要手工实现的挖掘策略，只不过它是连续可调的。实践中 SimCLR 用 0.1、MoCo 用 0.07，CLIP 干脆把它设成可学习参数。τ 太小的风险和无脑挑最难负样本一样，会死盯噪声样本导致训练不稳。

### Q3：为什么叫 InfoNCE？

> NCE 是 Noise Contrastive Estimation，把真实样本和噪声区分开的经典思路。Info 是因为它是互信息的变分下界——`I(a;p) ≥ log(N) − L`，最小化这个 loss 等于最大化正样本对之间互信息的下界。注意里面那个 log(N)，**负样本越多界越紧**，这从理论上解释了对比学习为什么需要大 batch。

### Q4：SimCLR 和 MoCo 的区别？

> 核心矛盾都是"怎么搞到足够多的负样本"。SimCLR 靠堆大 batch，需要 8192 才有足够负样本，对显存要求极高。MoCo 用一个队列存历史 batch 的特征当负样本，配合 momentum encoder 保证队列里的特征不会因为编码器更新太快而失效，这样小 batch 也能有几万个负样本。另外 BYOL 和 SimSiam 更极端，完全不用负样本，靠 predictor 加 stop-gradient 防止特征塌缩。

### Q5 ⭐：如果重做你的项目，你会怎么改损失函数？

（见 §8.3 —— 换 InfoNCE + 灰色地带 mask + 解决 batch 太小，三点都要说）
