## 1. 最终版简历措辞

> **Visual Place Recognition for SLAM Loop Closure** ｜ PyTorch, DINOv2, LightGlue, Metric Learning
>
> - 实现**四级回环检测前端**（全局检索 → 序列时序重排 → 几何验证 → 阈值门控），每一级均实现**经典与现代两套方案**并做对照消融；以受控变量设计分离视角与昼夜变化，量化出昼夜外观变化使 Recall@1 从 96% 降至 51%
> - 建立**验证集驱动的训练监控与模型选择**，发现原固定 5-epoch 配置在训练 loss 持续下降（0.125→0.002）的同时验证 Recall@1 从 0.80 单调劣化至 0.30；由此定位过拟合（泛化间隙 34.8 点），据此判断**问题不在训练策略而在特征本身**
> - 据此以 **DINOv2 零训练特征**替代微调 ResNet18，held-out Recall@1 **0.633 → 0.933**；并发现 CLS 与 patch-mean 聚合在 Recall@1 完全相同（0.933）时，**Recall@100%Precision 相差 5.4 倍**（0.167 vs 0.900）——即置信度校准质量的差异远大于精度差异
> - 量化 ORB 几何验证的**失效边界**（跨昼夜正确/错误配对内点比 1.1×，逐样本可分 56%，等同随机），据此替换为 **DISK+LightGlue** 并在完全相同的 RANSAC 判据下恢复至 **6.8×**，证实失效在描述子而非验证环节
> - 设计**开集评测协议**（移除部分 database 构造无匹配 query），使拒绝机制与 Recall@100%Precision 首次可被衡量；发现序列匹配将 R@100%P 从 0.233 提升至 0.686，**其置信度质量优于几何验证内点数**

### 1.1 为什么这样写

| 条目 | 展示什么能力 |
|---|---|
| 第 1 条 | 系统实现 + **实验设计**（受控变量） |
| 第 2 条 | **可观测性工程** + 诊断（loss 与指标脱节的实证） |
| 第 3 条 | **闭环能力**（归因 → 假设 → 验证 → **反向对照**） |
| 第 4 条 | **批判性**（主动量化方法失效边界，敢写负面结果） |

第 3、4 条最稀缺。大多数人只会写第 1 条。

> ⚠️ **第 3 条有个必须准备好的追问**："Recall@1 到 1.000 是不是过拟合/作弊？"
> 答：那 30 个 query 从未参与训练；而且我做了对照——**用完全未训练的 baseline 特征加同样的序列匹配也能到 1.000**，
> 所以这个 100% 主要是序列匹配的功劳，不是训练的功劳。同时 Gardens Point 是逐帧对齐、速度稳定的数据集，
> 完美满足序列假设，真实场景增益会小得多。**主动说破，比被问出来强。**

### 1.2 ⚠️ 三个数字的使用纪律

| 数字 | 能不能用 | 说明 |
|---|---|---|
| night_right **86%**（微调后全序列） | ❌ **不要单独用** | train-on-test，训练和评测同一批 query |

## 2. 最终版 60 秒自我介绍

> "这个项目做的是 SLAM 里的回环检测。机器人长时间运行会有累积漂移，需要识别出'我以前来过这里'来做位姿图优化修正。传统方案像 ORB-SLAM 用的 DBoW2 词袋基于手工特征，在光照剧变时不太行。
>
> 我做的是学习型全局描述子：预训练 ResNet18 去掉分类头，取全局平均池化后的 512 维特征做 L2 归一化，这样点积直接就是余弦相似度，检索就是一次矩阵乘法加 topk。
>
> 我先做了个受控变量的实验来量化能力边界——数据库用白天左侧，query 分两组，一组是白天右侧只变视角，一组是夜晚右侧同时变视角和光照。结果是纯视角变化 Recall@1 有 96%，加上昼夜变化掉到 51%。**这个对比把掉的 45 个点明确归因到了外观变化**。
>
> 然后我用 triplet loss 做度量学习，夜间图当 anchor、同位置白天图当正样本，把同一地点的昼夜图像在 embedding 空间拉近。为了不自欺欺人，我按时序切了训练和测试，只用前 70 帧训练，后 30 帧完全 held-out。结果 held-out 的 Recall@5 从 76.7% 提到了 100%，但 Recall@1 只从 50% 到 56.7%。
>
> **这个落差我做了归因**：训练区间 R@1 涨了 40 个点，held-out 只涨 6.7 个点；而训练之前这两个区间的差距只有 1.4 个点。所以这 33 个点的泛化间隙完全是训练造出来的——**模型学到的是可迁移的昼夜域变换，不是地点的精确判别能力**。
>
> 这个诊断我后来验证了：既然瓶颈在排序不在召回，那引入时序约束应该能修。我在相似度矩阵上做了序列匹配，用**完全没微调的**特征，Recall@1 从 51% 直接到 89%，而 Recall@10 几乎没动。**这反过来证明了诊断是对的。**"

**埋的钩子**（每个都通向一章）：DBoW2 对比（M8）、GAP 与池化（M2）、L2 归一化（M2/M6）、检索复杂度（M4）、受控变量设计（M1）、triplet 采样（M6）、时序切分（A3）、泛化间隙（A3/M7）、序列匹配（M8）。

## 5. 三个"陷阱题"的应对

### 5.1 「这不就是调包吗？」

**不要辩解，直接摆出你做的判断和实验。**

> "调用现成的 backbone 确实是的，但项目的价值不在那部分。我做的是三件事：
>
> **第一是实验设计。** 我用 day_right 作对照组把视角变化这个变量单独隔离出来，才能把性能下降明确归因到外观变化而不是视角。没有这个对照，96% 和 51% 就只是两个数字。
>
> **第二是诊断。** 我不满足于知道'夜间效果差'，而是去特征空间里量化了原因——夜间的类内类间相似度差距只有 0.081，是白天的一半，所以正确答案和干扰项的分数差被压到了噪声量级。这解释了为什么 R@10 有 87% 但 R@1 只有 51%。
>
> **第三是验证。** 基于这个诊断我提出假设：既然瓶颈在排序不在召回，引入时序约束应该能修 R@1 而不太动 R@10。实验结果是 R@1 从 51% 到 89%，R@10 只从 87% 到 91%。**假设被精确验证了。**
>
> 这些都不是调包能得到的。"

### 5.2 「为什么不用更好的方法（NetVLAD / DINOv2 / ...）？」

**先给理由，再证明你知道那些方法。**

> "项目的第一目标是先建立一个干净的最简基线，把'ImageNet 预训练特征本身的能力边界在哪'量化清楚。如果一开始就上 NetVLAD，我就分不清性能来自哪里。
>
> 我也清楚它们各自的代价：NetVLAD 输出是 K×D 维，64 个中心就是 32768 维，必须再接 PCA，训练还要配难样本挖掘；GeM 性价比最高，三行代码就能改；如果目标是跨域泛化，AnyLoc 那条用 DINOv2 零训练的路线在昼夜变化上可能比微调 ResNet18 更对症。
>
> 而且我做完诊断之后发现，**对我这个具体问题，序列匹配的性价比比换 backbone 高得多**——零训练加 38 个点。所以换更强的描述子不一定是最优先的事。"

### 5.3 「你怎么验证你的方法是有效的？」

**这题要主动暴露弱点，因为你确实有弱点。**

> "分两部分说。**有效的那部分**：我用了严格的时序 held-out，训练只用前 70 帧、测试用后 30 帧，而且我跑了训练前的 baseline 做对照——训练前两个区间的差距只有 1.4 个点，说明难度相当，所以训练后 34.8 个点的差距是可归因的。held-out 上 R@5 从 76.7% 到 100% 是真实的泛化。
>
> **不够的那部分**：我的训练循环里只打印了 loss，没有每个 epoch 评测检索指标，所以严格说我**不能确定 5 个 epoch 是不是最优的**——loss 下降本身不可靠，因为有 24% 的三元组 loss 恒为 0 会把平均值拽低，而且 loss 衡量的是 margin 满足程度不是排序质量。这是我优先级最高的改进项。
>
> 另外数据规模只有 100 帧，Recall@1 的一个点就是一张图，所以我只看量级变化，不看小数点后的差异。"

## 7. 面试前 30 分钟速览清单

**① 数字**（GLOSSARY §8）

```
day_right R@1 0.960    night_right R@1 0.510        ← 归因：外观 vs 视角
held-out  baseline R@5 0.767 → triplet R@5 1.000    ← 该报的成绩
泛化间隙  训练前 1.4 点 → 训练后 34.8 点             ← 过拟合证据
类内/类间相似度差距  白天 0.157 / 夜间 0.081         ← 机制解释
序列匹配  R@1 0.510 → 0.890（因果版 0.780）         ← 诊断的验证
```

**② 四句必背**

- "掉的 45 个点主要来自外观变化，不是视角变化"
- "模型学到的是可迁移的域变换，不是地点的精确判别能力"
- "不是找不到，是排不准"
- "VPR 的职责是候选召回，最终由几何验证拍板"

**③ 三个主动暴露的缺陷**（M7 §9 Q1 的 30 秒版）

过拟合（有量化）｜ 随机负样本 24% 零梯度 ｜ BatchNorm 域污染

**④ 两个术语纠正**

- 不要说"判别间隙"，说 **"类内/类间相似度差距"**（GLOSSARY 开头）
- VPR 的 Recall@K **不是**教科书 recall，是 hit rate@K（A4 §9）

**⑤ 一句收尾**

> "这个项目最大的收获不是那几个数字，而是学会了**先诊断再动手**——我先量化清楚瓶颈在排序而不在召回，才知道该做序列匹配而不是继续堆模型。"
