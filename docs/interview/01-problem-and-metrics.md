## 1. 先搞清楚 SLAM 在干什么

**SLAM = Simultaneous Localization and Mapping**，同时定位与建图。拆成两件事：

- **定位**：我现在在哪？
- **建图**：周围长什么样？

**难点在于两者互相依赖**：

> 你要知道自己在哪，才能把看到的东西正确画进地图；
> 但你又得先有地图，才能知道自己在哪。

**先有鸡还是先有蛋。** 这就是名字里 "Simultaneous"（同时）的含义。

### 1.1 一个概念：位姿（pose）

"我在哪"包含两部分：**位置**（x,y,z）+ **朝向**（绕三轴各转多少），合起来叫**位姿**，共 **6 个自由度（6-DoF）**。

（这就是 B1 里 `SE(3)` 是 6 维的原因——3 平移 + 3 旋转。）

## 2. 漂移是怎么产生的

### 2.1 比喻：闭着眼睛走路

闭眼在房间里走，只能靠感觉记账：

```
"我向前走了 3 步，然后左转 90 度，又走了 5 步……"
```

**每一步都有一点误差**——以为走了 3 步，实际 3.1 步；以为转了 90 度，实际 88 度。

**单次误差很小，但会累积**：走 10 步误差 10 厘米无所谓；走 1000 步误差可能 5 米——**你以为在门口，其实站在房间中央**。

**这就是漂移（drift）。**

### 2.2 为什么它不会自愈

里程计（visual odometry）估的是**相邻两帧之间的相对运动**。全局位置是把这些相对运动**一个个接起来**：

```
T_世界←第k帧 = T_世界←第0帧 · T_第0←第1 · T_第1←第2 · … · T_第k-1←第k
```

> 📌 **第 1000 帧的位置依赖前面 999 步的全部估计。**
>
> 第 5 步偏了一点，第 5 步之后的**所有位置全都跟着偏**——而且**永远不会被纠正**，因为后面每步只知道"相对上一步"，不知道"绝对在哪"。

**误差增长速度**：随机噪声大致按 **√t**，系统性偏差（如尺度一直偏大 1%）按 **t** 线性。

### 2.3 实际后果

绕一栋楼走一圈回到起点，估计会说"我在离起点 5 米处"。地图上**同一面墙被画了两次，错开 5 米**——俗称"鬼影"、"双层地图"。

## 3. 回环检测怎么修正漂移

### 3.1 回到比喻

闭眼走了很久，突然**摸到一个熟悉的桌角**，认出来了：**"这是我出发的那张桌子！"**

这一瞬间你获得了极宝贵的信息：

> **我的记账说我离出发点 5 米，但实际上我就在出发点。**
> **所以这 5 米误差，是一路累积出来的。**

**有了它，就能回头把中间所有估计都往回修正。这就是回环检测。**

### 3.2 用 SLAM 的语言

系统维护一个**位姿图（pose graph）**：节点 = 每个关键帧的位姿，边 = 两个位姿之间的约束。

**里程计只提供"相邻节点"之间的边**：

```
①—②—③—④—⑤—⑥—⑦—⑧      ← 一条链
```

**回环检测提供一条"跨越时间的远距离边"**：

```
①—②—③—④—⑤—⑥—⑦—⑧
└──────────────────┘        ← 回环边：第 8 帧和第 1 帧是同一地点
```

**图从"一条链"变成"一个环"**，然后**位姿图优化**（g2o / GTSAM / Ceres）调整所有节点，让所有边的约束尽量满足——**累积误差被沿整条轨迹摊平**。

> 📌 **本章最该记住的**：
>
> **里程计只能减缓误差增长，回环检测是唯一能真正"消除"累积误差的机制。**
>
> 没有它 SLAM 就退化成"里程计 + 拼接"，那个 "S"（Simultaneous）根本不成立。

## 4. 误检与漏检的代价，极度不对称 ⭐

这是本章最重要的洞察，它决定了后面所有的指标取舍。

| | 是什么 | 后果 | 可恢复性 |
|---|---|---|---|
| **漏检 FN** | 来过但没认出来 | 少一次修正机会，漂移继续 | **可恢复**——下次经过还有机会 |
| **误检 FP** | 没来过却以为来过 | **把两个不同地点焊在一起** | **灾难性，通常不可逆** |

### 4.1 误检为什么是灾难

回到比喻：摸到一个桌角以为是出发点那张——**其实是房间另一头另一张长得一样的桌子**。

于是你"确信"我在出发点，**把整个记账按这个错误信息修正了一遍。结果整个地图被折叠错了。**

SLAM 语言：位姿图里被加了一条**错误的边**，优化器会**强行把两个不相干的地方拉到一起**。优化是全局的，**一条错边会把整张地图都扭曲掉**。

> 📌 **一句话：宁可漏，绝不能错。**

### 4.2 工业系统的三层保险

1. **几何验证**：局部特征匹配 + RANSAC 检查几何一致性（详见 [B1](B1-slam-geometry.md)）
2. **时序/共视一致性**：ORB-SLAM 要求**连续 3 个关键帧**都检测到同一回环才接受
3. **鲁棒后端**：Huber 核、switchable constraints，让优化器能**事后否决**一条边

---

## 5. 但这里有个容易推反的地方 ⭐

"误检是灾难性的"很容易推出"**所以要追求高 precision**"。**这个推论对，但用错地方就全错。**

### 5.1 回环检测是分阶段的

```
① 候选检索（本项目）  →  ② 几何验证  →  ③ 一致性检查  →  ④ 加边优化
   宽松，给一堆候选        严格，剔除错的      更严格           最终决策
```

**这是一个逐级收紧的漏斗。**

- **第①层要高 recall**：正确答案**只要进候选池**就行，后面第②层负责剔除错的
- **最终 precision 由第②③层保证**，不是第①层

### 5.2 为什么第①层不能追求 precision

> **第①层漏掉的，后面永远救不回来。** 候选池里没有正确答案，几何验证再准也白搭。
>
> 而第①层多给几个错的，代价只是**多跑几次几何验证**——那是算力成本，不是能力上限。

> 📌 **这就是 VPR 主指标是 Recall@K 的原因。** 不是"precision 不重要"，而是 **precision 在下游被保证了，而 recall 在下游无法弥补**。

⚠️ **必须打的补丁**：K 不能无限大。每个候选都要跑一次几何验证，K 直接决定在线开销。准确说法是「**在可接受的 K 下追求高 recall**」——不加这句会被反问"那 K 取 100 不就 100% 了？"

## 6. VPR 与相邻概念的边界

| 任务 | 输入 → 输出 | 核心诉求 |
|---|---|---|
| **图像检索 CBIR** | 图 → 视觉上相似的图 | **相似本身就是目标** |
| **视觉地点识别 VPR** | 图 → **同一地点**的图 | 相似只是**手段** |
| **视觉重定位** | 图 → **6-DoF 位姿** | 不只"哪个地点"，还要精确位姿 |
| **回环检测** | 当前帧 → 历史同地点帧 | VPR 在 SLAM 里的落地 |

### 6.1 VPR vs 图像检索：本质区别

**图像检索**：两张夜景图很像 → 成功。

**VPR**：一张夜景图和一张白天图是同一地点 → **必须检索到**，哪怕像素层面毫无相似性。反过来，两条不同走廊长得几乎一样 → **必须区分开**。

> 📌 **VPR 追求的不变性，经常和"视觉相似"是冲突的。**
>
> 你要让模型**忽略**光照/天气/季节这些巨大差异，同时**抓住**细微的、能区分地点的线索。

### 6.2 VPR vs 重定位：一个好用的说法

**VPR 通常是重定位的第一步。** 现代标准流程（如 hloc）：

```
NetVLAD 全局检索 Top-K  →  SuperPoint/SuperGlue 局部匹配  →  PnP + RANSAC 解 6-DoF
        ↑
   本项目做的正是这一步
```

> 面试说出这句能**直接把 side project 挂到 SOTA pipeline 上**。

## 7. VPR 的两类挑战

| 挑战 | 是什么 | 本项目 |
|---|---|---|
| **外观变化** appearance/condition change | 昼夜、季节、天气、光照 | ✅ **主攻**（`night_right`） |
| **视角变化** viewpoint change | 横向偏移、朝向、远近 | ✅ 覆盖（`day_right`） |
| **感知混叠** perceptual aliasing | **不同地点长得几乎一样** | ⚠️ 存在但未专门处理 |
| 动态物体/遮挡 | 行人、车辆 | ❌ 未涉及 |

**"感知混叠"这个词要会说**——指"两条相似走廊""两排一样的树"。README 里 `night_failure_103.png` 那个失败案例就是它。

## 8. 数据集选择其实是个实验设计 ⭐

### 8.1 三个序列的角色

```
database:  day_left     ← 基准条件
query 1:   day_right    ← 相对基准，只变了【视角】
query 2:   night_right  ← 相对基准，变了【视角 + 外观】
```

**`day_right` 是对照组**，它把"视角变化"这个变量**单独隔离**出来。

### 8.2 为什么这很重要

只测 `night_right` 得到 51%，你只能说"效果不好"，**不知道是因为视角还是因为昼夜**。

有了对照组：

```
day_right   96%   ← 只有视角变化
night_right 51%   ← 视角 + 外观变化
```

**两者相减就能归因**：

> **掉的 45 个点，主要来自外观变化，不是视角变化。**

> 📌 **这才是"96% vs 51%"的真正价值**——它不是两个孤立的数，而是一次**变量归因**。
>
> 后面所有度量学习工作，都是**因为这次归因指向了"外观"才做的**。动机链在这里闭合。

### 8.3 为什么 database 用白天、query 用夜晚

符合**真实部署**：**建图通常在条件良好时离线完成，定位发生在任意条件下。** 这个不对称是刻意的。

## 9. 真值是怎么来的

### 9.1 机制

三个序列**沿同一路线逐帧对齐采集**，同编号图像大致对应同一地点：

```
query/night_right/Image023.jpg   ←对应→   database/day_left/Image023.jpg
```

**图像编号就是位置标签。** 检索结果编号与 query 编号相差 ≤3 即判正确。

### 9.2 tolerance 为什么是 ±3 不是 0

**相邻帧本来就是同一地点**（只隔一两步）。tolerance=0 的话，检索到 `Image022` 会被判**错**，但它其实是完全正确的候选——**指标会严重低估真实性能**。

±3 帧约几步位移，是"承认地点有空间外延 + 容忍采集对齐误差"的合理设定。

> ⚠️ **但要能说出它的任意性**：3 没有物理依据（不是"3 米"也不是"5 度"）。换成 ±2 或 ±5 数字就会变。
>
> **所以真正有意义的是"同一 tolerance 下的横向对比"**，而不是"我达到了 96%"这个孤立数字。

### 9.3 三个局限（要主动说）

1. **不是度量真值**：没有 GPS/位姿，说不出"误差在 5 米内"
2. **假设两次采集速度一致**：走路快慢不同则同编号帧的物理位置错开，**真值本身带噪**
3. **规模极小**：100 张 database、200 张 query。**Recall@1 一个点 = 一张图**

> 💡 **一个能加分的说法**：
> "这个规模下几个点的差异我当噪声看，所以我更看重 R@5 从 76.7% 到 100% 这种**量级变化**，而不是小数点后的差异。"

## 10. 指标部分

**详见 [A4-metrics.md](A4-metrics.md)** —— 那里用三个真实检索结果手把手算了 Recall@K 和 Precision@K。

本章只需记住结论：

- **Recall@K**：Top-K 里"有没有"对的（0 或 1），平均后就是**成功率**
- **Precision@K**：Top-K 里"有几个"对的 ÷ K
- **⚠️ VPR 的 Recall@K 不是教科书 recall**，是二值命中率（hit rate@K）
- **VPR 重 recall 的理由见 §5**

### 10.1 这套评测体系还缺什么

| 缺口 | 影响 |
|---|---|
| **Recall@100%Precision** | SLAM 回环的经典指标（零假阳性下能召回多少）。v2 加了拒绝机制后已可计算，见 [experiments.md](../experiments.md) |
| **PR 曲线 / AUC** | 单点指标信息量太小 |
| **distractor（干扰集）** | 本项目是**闭集**——每个 query 必有正确答案。真实场景有海量不相关图像 |
| **真实度量真值** | 标准 benchmark（Pitts30k、MSLS）用 **GPS 25 米**定义正确 |

## 11. 面试怎么答

### Q1：为什么 SLAM 需要回环检测？不做会怎样？

> 里程计估的是帧间相对位姿，全局位置是把它们一步步接起来的，所以误差会累积而且不会自愈——第 5 步偏了，后面所有位置都跟着偏。走得越远漂移越大，绕一圈回到原点轨迹闭合不上，地图上会出现同一面墙的两个副本。
>
> 回环检测提供的是跨越时间的全局约束——识别出"当前帧和很久以前某帧是同一地点"，就能在位姿图里加一条边，让优化把累积误差沿整条轨迹摊平。**它是 SLAM 里唯一能真正消除、而不只是减缓累积误差的机制。**

### Q2：假阳性回环有什么后果？

> 灾难性的。位姿图优化会把两个不同地点强行拉到一起，而且优化是全局的，一条错边会把整张地图都扭曲掉，通常不可逆。相比之下漏检只是少一次修正机会，下次经过还有机会。
>
> 所以工业系统会做三层保护：几何验证用 RANSAC 检查内点数、时序或共视一致性要求连续多帧确认、后端用鲁棒核或 switchable constraints 让优化器能事后否决这条边。

### Q3 ⭐：那你为什么说 recall 比 precision 重要？这不矛盾吗？

> 不矛盾，关键是**分清哪一层**。回环检测是个逐级收紧的漏斗：候选检索 → 几何验证 → 一致性检查 → 加边。误检灾难性所以要高 precision，**那是最终阶段的要求**。
>
> 我做的是第一层。这一层要高 recall，因为**正确答案只要进了候选池，后面的几何验证就有机会确认它；而第一层漏掉的，后面永远救不回来**。第一层多给几个错的，代价只是多跑几次几何验证，那是算力成本不是能力上限。
>
> 当然 K 不能无限大——每个候选都要跑一次几何验证，K 直接是在线开销。所以准确说法是"在可接受的 K 下的高 recall"。

### Q4：VPR 和图像检索有什么区别？

> 图像检索的目标就是"相似"，相似本身即成功。VPR 的目标是"同一地点"，相似只是手段。关键差别是 VPR 必须对拍摄条件不变——一张夜景图和一张白天图在像素层面几乎没有相似性，但它们是同一地点必须被检索到；反过来两条不同走廊长得很像，却必须被区分开，这叫感知混叠。**所以 VPR 追求的不变性经常和"视觉相似"是冲突的。**

### Q5 ⭐：你的数据集是怎么设计的？

> 三个序列走的是同一条路线：database 用 day_left，query 分两组，day_right 只变了视角，night_right 同时变了视角和光照。
>
> **day_right 是对照组**——它把"视角变化"这个变量单独隔离出来了。所以 96% 和 51% 不只是两个数字，而是一次归因：**掉的 45 个点主要来自外观变化，不是视角变化**。我后面做度量学习就是因为这次归因指向了外观。
>
> 另外 database 用白天、query 用夜晚这个不对称是刻意的——真实部署就是建图在条件好的时候离线做，定位发生在任意条件下。

### Q6：你的 ground truth 可靠吗？

> 三个序列是逐帧对齐采集的，所以图像编号就是位置标签，帧号差 ≤3 判正确。tolerance 设 ±3 是因为相邻帧物理上就是同一地点，设成 0 会把正确候选误判为错误。
>
> 但我清楚它的局限：它不是度量真值，说不了误差多少米；它假设了两次采集速度一致，真值本身带噪；而且规模只有 100 张，Recall@1 的一个点就是一张图。所以我更看重量级上的变化，比如 R@5 从 76.7% 到 100%，而不是小数点后的差异。
>
> 还有一点，±3 这个数没有物理依据，换成 ±2 或 ±5 数字就变了。**所以真正有意义的是同一 tolerance 下的横向对比，不是绝对值。**
