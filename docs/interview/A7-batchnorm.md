# 附录 G · BatchNorm

> 第一梯队 ②，**优先级最高的一章**——因为简历上有一条基于 BatchNorm 的成果
> （M7 §4 域统计量污染）。掌握它的**行为**不够，必须掌握**数学**和**为什么有效**，
> 否则被追问一句原理，整条 bullet 会变成"像是别人告诉他的"。

---

## 1. 它要解决什么问题

一个 50 层的网络，第 30 层的输入是前面 29 层共同作用的结果。

**每次参数更新后，前面 29 层全变了，第 30 层看到的输入分布也跟着变。** 它刚适应一种分布，下一步分布又变——像在**追一个不断移动的目标**。层数越深越严重。后果：

- 必须用**很小的学习率**，否则一步走太大，后面所有层输入分布剧变，训练崩
- 对**权重初始化极度敏感**
- 训练**很慢**

**BN 的想法很直接**：既然每层输入分布老是乱跑，就**在每层强行把它掰回标准形态**。

---

## 2. 公式：就四步

```
① μ  = 这一批数据的均值
② σ² = 这一批数据的方差
③ x̂  = (x − μ) / √(σ² + ε)        ← 归一化：均值0、方差1
④ y  = γ · x̂ + β                  ← 缩放平移（γ、β 可学习）
```

`ε` 默认 1e-5，防止方差为 0 时除零。

### 2.1 手算验证（实测）

输入 8 个数 `[1,2,3,4,5,6,7,8]`：

```
均值 μ  = 4.5000
方差 σ² = 5.2500

BN 输出  : [-1.5275, -1.0911, -0.6547, -0.2182, 0.2182, 0.6547, 1.0911, 1.5275]
手算结果 : [-1.5275, -1.0911, -0.6547, -0.2182, 0.2182, 0.6547, 1.0911, 1.5275]
一致: True ✓

输出均值 -0.000000, 方差 1.0000
```

验算第一个：`(1 − 4.5) / √5.25 = −3.5 / 2.2913 = −1.5275` ✓

> ⚠️ **易被追问的细节**：归一化用的是**有偏方差**（除以 N），但更新 `running_var` 时 PyTorch 用**无偏**（除以 N−1）。

---

## 3. γ 和 β 为什么必须存在 ⭐

只做到第 ③ 步看起来已达目的了，**为什么还要第 ④ 步把它再缩放平移回去？**

**因为强行归一化会削弱表达能力。**

最清楚的例子：假设激活函数是 `sigmoid`。sigmoid 在 **0 附近几乎是直线**（接近线性），只有远离 0 才有明显非线性。

如果把每层输出强行压到均值 0 方差 1，绝大部分数值落在 0 附近的**近似线性区**——**网络的非线性丢了**，堆再多层等价于一层线性变换。

所以第 ④ 步给网络一个**反悔的机会**：

- 想要标准分布 → 保持 `γ≈1, β≈0`
- 想要更大方差 → 把 `γ` 学大
- **极端情况：学到 `γ=σ, β=μ` 就完全撤销了归一化，退回原样**

> 📌 **一句话**：**前三步是"强制标准化"，第四步是"允许网络反悔"。**
> 归一化解决优化问题，γβ 保住表达能力，缺一不可。

## 4. 沿哪个维度统计？⭐ 最容易搞错

对 `[N, C, H, W]`，BN 对谁求均值？**答案藏在参数形状里**（实测）：

```
BatchNorm2d(64) 作用于 [N, 64, H, W]
  weight (gamma)   形状 (64,)    -> 每个【通道】一个值
  bias   (beta)    形状 (64,)
  running_mean     形状 (64,)
  running_var      形状 (64,)
```

**形状是 `(64,)`，每个通道一个数，所以：**

> **BatchNorm 对每个通道单独统计，统计时跨越 N、H、W 三个维度。**

第 0 通道的均值 = 这一批所有样本、所有空间位置上第 0 通道的值全部求平均。

**为什么合理？** 一个通道代表**一种特征**（如"垂直边缘"）。归一化对象应是"这种特征在整批数据上的响应强度"，而不是把不同特征混在一起。

### 4.1 四种 Norm 的区别，只在"沿哪些维度统计"

| 归一化 | 统计维度 | 特点 | 用于 |
|---|---|---|---|
| **BatchNorm** | 跨 N,H,W，每个 C 一组 | **依赖 batch** | CNN |
| **LayerNorm** | 跨 C,H,W，每个 N 一组 | **不依赖 batch** | **Transformer** |
| **InstanceNorm** | 跨 H,W，每个 (N,C) 一组 | 每样本每通道独立 | 风格迁移 |
| **GroupNorm** | C 分组，组内跨 C,H,W | **不依赖 batch** | **小 batch 替代 BN** |

> 💡 **记忆抓手**：**只有 BatchNorm 依赖 batch**，这是它一切优点和一切麻烦的根源。Transformer 用 LayerNorm 正是因为 NLP 序列长度不一、batch 统计不稳。

**参数量极小**：`2 × C`。64 通道只有 128 个参数。

## 5. train 和 eval 两套行为

**训练时**：用**当前 batch** 的 μ、σ²，同时滑动平均累积：

```
running_mean = (1 − momentum) × running_mean + momentum × 当前batch均值
```

（PyTorch `momentum` 默认 0.1，含义是"新值占的比重"，和优化器的 momentum 完全不同。）

**推理时**：用累积好的 `running_mean/var`，不再看当前 batch。

### 5.1 为什么推理不能用 batch 统计量

**① 推理时 batch 可能只有 1 张图**，一个样本的方差是 0，公式崩。

**② 更根本：推理结果不应依赖同批的其他样本。**

M3 实测：同一张图放进"全白天"和"全夜间"两个 batch，`train()` 模式下特征余弦只有 **0.796**。

**对检索这是致命的**——整个系统的前提是"同一张图必须映射到同一个向量"。

## 6. BN 为什么有效？这里有个反转 ⭐

### 6.1 原论文的解释（2015）

BN 论文提出 **Internal Covariate Shift（ICS）**，说 BN 有效是因为**减少了 ICS**——也就是 §1 说的"每层输入分布不断变化"。

**很多人到今天还只会背这个答案。**

### 6.2 但它后来被强烈质疑

**Santurkar et al., NeurIPS 2018《How Does Batch Normalization Help Optimization?》** 做了两个关键实验：

1. 在 BN 之后**人为注入噪声**制造严重 ICS —— 训练**照样又快又好**
2. 直接测量 ICS —— 发现加了 BN 之后 ICS **并没有明显减少**

结论：**BN 的效果和 ICS 基本没关系。**

### 6.3 目前更被接受的解释

> **BN 让损失曲面变得更平滑（smoother optimization landscape）。**

它让梯度变化更平缓、更可预测（数学上是 Lipschitz 常数变小）。梯度可预测意味着：**可以放心迈大步，不用担心走一步掉进悬崖。**

这直接解释了 BN 最实际的好处——**能用大得多的学习率**。

### 6.4 实测验证

六层小网络，SGD，60 步：

```
学习率   | 无 BN 的最终 loss  | 有 BN 的最终 loss
---------|-------------------|------------------
0.01     | 0.6966            | 0.6931
0.1      | 0.6930            | 0.6627
0.5      | 0.6930  ← 卡死    | 0.0075  ← 学会了
```

（0.6931 = ln2，二分类的随机猜测水平，说明完全没学到东西。）

**lr=0.5 时无 BN 完全卡住，有 BN 降到 0.0075。**

### 6.5 面试标准答法

> "原论文的解释是减少 Internal Covariate Shift，但这个说法在 2018 年 Santurkar 那篇 NeurIPS 论文里被基本推翻了——他们在 BN 后人为注入噪声制造 ICS，训练照样很好；直接测量也发现 BN 没有显著减少 ICS。目前更被接受的解释是 BN 让损失曲面更平滑、梯度更可预测，从而允许用大得多的学习率。我自己验证过，六层小网络在 lr=0.5 时没有 BN 完全训不动，加了 BN 能收敛到 0.0075。
>
> 说实话这是个**效果非常确定、但机理至今仍有争议**的技术。"

**最后那句很值钱**——显示你知道这个领域的真实状态，而不是背了一个过时结论。

## 7. BN 的坑

### 7.1 坑一：batch 小时统计量不可靠（实测）

衡量 batch 均值偏离真实均值多少：

```
batch size | 偏差
    2      | 0.0713
    4      | 0.0522
    8      | 0.0348
   16      | 0.0259
   32      | 0.0170
  128      | 0.0088
```

误差大致按 **1/√batch** 下降（和 A1 梯度噪声同一规律）。**batch < 8 时统计量已相当不可靠。** 所以：

- 检测/分割任务（显存吃紧，batch 常只有 2-4）普遍改用 **GroupNorm**
- **小数据微调常直接冻结 BN**，用预训练的 running stats——ImageNet 上 128 万张图统计的，比你用 16 张算的可靠得多

> 📌 这正是 M7 §4.3 的**方案 B**。本项目 batch=16，正好在边缘地带。

### 7.2 坑二：域混合 ← **本项目的发现** ⭐

有了公式就能把 M7 §4 讲透：

```python
anchor_features   = model(anchor)      # anchor 全是【夜间】图
positive_features = model(positive)    # positive 全是【白天】图
```

用 BN 公式重新表述：

- 第一次 forward：batch 全夜景 → 算出 `μ_夜, σ_夜`（夜景偏暗，均值低）
- 第二次 forward：batch 全白天 → 算出 `μ_昼, σ_昼`（完全不同）

于是：

```
anchor   经过的是  (x − μ_夜) / σ_夜
positive 经过的是  (x − μ_昼) / σ_昼
```

> **两个分支用了两个不同的归一化函数——输出根本不在同一个坐标系里。**
> **而 loss 却在计算这两个向量之间的距离。**

这就是实测 anchor 特征余弦只有 **0.8655**、训练信号差 **24%** 的原因。

合并成一个 batch 后，BN 看到昼夜混合分布，算出**同一套** μ、σ，三个分支才在同一坐标系里。

### 7.3 坑三：running stats 被反复拉扯

实测：一个训练 step 内 `running_mean` 被 anchor（全夜）和 positive（全昼）先后更新，**两次更新方向的余弦是 −0.2367**——朝相反方向拉。最终统计量是个"三不像"，而**推理时用的正是它**。

## 8. 两个工程细节

### 8.1 顺序：`Conv → BN → ReLU`

BN 放在**激活之前**。直觉：先把分布掰正再送进非线性，数值落在激活函数的"有效工作区"而非饱和区。

（也有 `BN → ReLU → Conv` 的变体，叫 pre-activation ResNet，在很深的网络里更好。知道有这回事即可。）

### 8.2 有 BN 时，前面的 Conv 不要 bias（实测）

```
ResNet18 的 conv1 有 bias 吗: False
layer1[0].conv1 有 bias 吗  : False

实验: 给 Conv 加 bias=100，经过 BN 后输出是否改变: 否，完全一致
```

**为什么？** Conv 的 bias 给每个输出通道加一个**常数**，而 BN 第一步就是**减去均值**——这个常数被完全减掉：

```
加了 bias b：  (x + b) − (μ + b) = x − μ     ← b 被完全抵消
```

所以 bias **加了也白加**，纯属浪费参数。而且 BN 的 `β` 本来就扮演偏移的角色。

> 💡 看到 `nn.Conv2d(..., bias=False)` 就应立刻反应过来"后面接了 BN"。

## 9. 小结

| 要点 | 内容 |
|---|---|
| **解决什么问题** | 深层网络每层输入分布随训练变化，只能用小学习率、对初始化敏感 |
| **四步公式** | 算 μ → 算 σ² → 归一化 → **γ·x̂ + β** |
| **γβ 为什么必须有** ⭐ | 强行归一化削弱非线性；γβ 给网络**反悔的机会**（γ=σ,β=μ 时完全撤销） |
| **沿哪维统计** ⭐ | **每通道一组，跨 N,H,W**。参数形状 `(C,)` 就是证据 |
| **四种 Norm** | **只有 BN 依赖 batch**；LayerNorm→Transformer，GroupNorm→小 batch |
| **train/eval** | 训练用 batch 统计量并累积；推理用 running stats。**结果不能依赖同批其他样本** |
| **为什么有效** ⭐ | 原论文说减少 ICS，**2018 年被基本推翻**；现解释为**损失曲面更平滑**→可用大学习率。实测 lr=0.5 无 BN 训不动、有 BN 收敛 0.0075 |
| **小 batch 坑** | 误差按 **1/√batch**，batch<8 已不可靠 → GroupNorm 或冻结 BN |
| **域混合坑** ⭐ | **本项目的发现**：两分支用了两套 μσ，输出不在同一坐标系，loss 却在比距离 |
| **Conv 不要 bias** | BN 减均值时把常数 bias 完全抵消 |
