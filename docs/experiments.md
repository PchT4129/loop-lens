# 消融实验

所有配置均在 **严格 held-out 段 `night_right` Image070–099（30 个 query）** 上评测。
该段从未参与任何训练：训练用 `000-059`，验证用 `060-069`，database 训练时截断到 `056`（purged gap）。

复现：`bash scripts/run_ablation.sh night_right`

---

## 1. 主表

| # | 配置 | R@1 | R@5 | R@10 | P@5 | R@100%P |
|---|---|---:|---:|---:|---:|---:|
| ① | Baseline：预训练 ResNet18，零训练 | 0.500 | 0.767 | 0.900 | 0.433 | 0.000 |
| ② | v1 Triplet（5 epoch 固定 / 无验证 / 无增强 / Adam / 三次 forward） | 0.567 | **1.000** | 1.000 | 0.493 | 0.133 |
| ③ | **v2 Triplet**（BN 修复 + ColorJitter + AdamW + 验证集早停 + purged gap） | **0.633** | 0.967 | 1.000 | **0.607** | 0.033 |
| ④ | ③ + 序列匹配（**因果**，仅用过去帧 = 在线 SLAM 条件） | **1.000** | 1.000 | 1.000 | 0.893 | **1.000** |
| ⑤ | ③ + 序列匹配（非因果，离线/批处理） | **1.000** | 1.000 | 1.000 | **0.913** | **1.000** |
| ⑥ | ⑤ + 几何验证（**门控**模式） | 1.000 | 1.000 | 1.000 | 0.913 | 1.000 |
| ⑦ | ⑤ + 几何验证（**重排**模式）⚠️ 负面结果 | 0.667 | 1.000 | 1.000 | 0.647 | 0.033 |

`R@100%P` = Recall@100%Precision，即"在一个假阳性都不产生的判定阈值下能召回多少"。
SLAM 里假阳性回环会撕裂地图且不可逆，所以这个指标比平均精度更贴近真实需求。

## 2. 逐行解读（含不好看的部分）

### ② → ③：训练流程修复

**改善**：单帧 R@1 `0.567 → 0.633`，P@5 `0.493 → 0.607`（候选列表明显更干净）。

**⚠️ 但两项变差了**，如实记录：

- `R@5` 从 1.000 掉到 0.967（30 个 query 里多错 1 个）
- `R@100%P` 从 0.133 掉到 0.033

对这两项的诚实解读：样本量只有 30，R@5 差 1 个 query 就是 3.3 个百分点，落在噪声范围内。
`R@100%P` 是个极端敏感的指标——只要置信度最高的那个 query 判错，整个指标就塌到接近 0，
所以它在小样本上的方差非常大，不宜单独解读。

另外 ③ 的训练数据比 ② **少了 10 帧**（`060-069` 划给了验证集）。
这是获得模型选择能力必须付出的代价，不是免费的改进。

### 训练过程本身：loss 与指标的脱节 ⭐

v2 训练的完整日志：

```
Epoch 1: loss 0.1246 | val R@1 0.8000   <- best
Epoch 2: loss 0.0308 | val R@1 0.7000
Epoch 3: loss 0.0085 | val R@1 0.6000
Epoch 4: loss 0.0052 | val R@1 0.5000
Epoch 5: loss 0.0020 | val R@1 0.3000   -> 早停
```

**训练 loss 单调下降到 0.002，验证 Recall@1 单调下降从 0.80 到 0.30。**

这是"loss 下降 ≠ 检索变好"的直接实证，也说明**原来那个固定 5 epoch 的配置多训了 4 个 epoch**，
从第 2 个 epoch 开始就在持续损害泛化。没有验证集就完全看不见这件事。

loss 之所以会骗人，有两个原因：一是三元组一旦满足 margin 后 loss 恒为 0，
大量"已学会"的样本把平均值往下拽；二是 loss 衡量的是 margin 满足程度，不是排序质量。

### ③ → ④/⑤：序列匹配 ⭐

R@1 `0.633 → 1.000`，R@100%P `0.033 → 1.000`。

**但必须说清楚这 100% 是怎么来的**——我做了两个对照：

| 对照 | 结果 | 说明 |
|---|---|---|
| **A. baseline 特征 + 同样的序列匹配** | R@1 = **1.000** | 说明这 100% **几乎全部来自序列匹配本身，不是来自 triplet 训练** |
| **B. 打乱 query 时序后再做序列匹配** | R@1 = **0.300** | 说明实现确实在利用时序结构，不是某种顺序无关的假象 |

所以正确的表述是：

> **在这个 30 帧片段上，序列匹配单独（零训练）就能达到 R@1 = 100%；triplet 训练的贡献在开启序列匹配后基本被覆盖。**

⚠️ **还要说清这个 100% 的前提**：Gardens Point 的三个序列是**逐帧对齐**采集的，
两次行进速度几乎一致，正好完美满足序列匹配"速度比 = 1"的假设。
真实部署中速度会变化、会转向、会走岔路，需要在多个速度上搜索，增益会明显小于此。
30 个 query 的样本量也偏小。

**triplet 训练是否还有价值？** 有——它提升的是**单帧**能力（R@1 0.500→0.633，P@5 0.433→0.607），
而单帧能力恰恰是序列假设失效时（机器人原地转向、刚启动、走岔路）唯一能依靠的东西。

### ⑥ vs ⑦：几何验证的适用边界 ⭐

**⑦ 重排模式把 R@1 从 1.000 打回 0.667。** 这是个负面结果，但它比正面结果更有信息量。

为什么？关键在于**两个任务的难度完全不同**（内点数实测）：

| 任务 | day_right（同域） | night_right（跨昼夜） |
|---|---|---|
| 判别"是不是同一地点"（正确配对 vs 随机远处配对） | 134.7 vs 26.1 → **100% 可分** | 28.7 vs 27.0 → **40~53%，等同随机** |
| 在 Top-10 内部排序（正确候选 vs 错误候选） | 58.1 vs 40.2 → 有信号但方差大 | 25.1 vs 24.4 → **基本无信号** |

两点结论：

1. **ORB 在跨昼夜配对上判别力接近随机。** 原因是 ORB 依赖图像梯度构造二值描述子，
   昼夜之间梯度结构本身就变了，能通过 ratio test 的匹配大多是虚假的；
   而基础矩阵有 7 个自由度，在几十个随机匹配里凑出一个"看似成立"的模型并不困难。

   > **这从一个独立角度验证了整个项目的前提**：传统手工特征扛不住光照剧变，
   > 这正是需要学习型描述子的原因。下一步应换成 SuperPoint + LightGlue。

2. **即使在同域，几何验证也不该用来重排。** Top-K 候选全是相隔几帧的近似图像，
   ORB 内点数无法在它们之间可靠排序；而 CNN 的 top-1 已经相当准，
   用高方差信号去重排只会把对的挤下去（day_right 上 R@1 0.967 → 0.833）。

   **几何验证在真实 SLAM 里的角色是【门控】而不是【排序器】**——这也正是 ORB-SLAM 的用法。
   所以 `--geometric-mode` 的默认值设为 `gate`。

⑥ 门控模式在本表里指标与 ⑤ 完全相同，因为此时所有 top-1 都已正确，门控没有可拒绝的对象。
它的价值要在有真正负样本（机器人处于全新地点）的开集设定下才能体现——这是本项目评测体系仍缺的一环。

## 4. 这套实验体系仍缺什么

| 缺口 | 影响 |
|---|---|
| **开集设定** | 每个 query 必有正确答案，没有 distractor，也没有"机器人在全新地点"的负样本。门控机制的价值无法体现 |
| **样本量** | held-out 只有 30 个 query，1 个 query = 3.3 个百分点，小数点后不可解读 |
| **验证集只有 10 帧** | 模型选择的粒度粗（R@1 只能取 0.1 的倍数） |
| **单一环境** | 一条校园路线，结论不能外推到城市尺度 |
| **序列假设过于理想** | 数据集逐帧对齐，速度一致，对序列匹配过于友好 |
| **无真实度量真值** | 用帧号差代替距离，说不出"误差在几米内" |

---

## 5. 结论

1. **验证集驱动的模型选择是所有改动里最重要的一项**——它揭示了原配置多训 4 个 epoch，
   而这件事在只看 loss 时完全不可见。
2. **序列匹配是本数据集上性价比最高的手段**：零训练、零参数，单独就能把 R@1 打到 100%。
   但它的增益强烈依赖"轨迹连续且速度稳定"这个前提。
3. **triplet 训练的价值在单帧场景**（R@1 +13.3 点，P@5 +17.4 点），
   即序列假设失效时的兜底能力。
4. **ORB 几何验证在跨昼夜场景下不可用**，且即使在同域也只应作门控而非排序器。
   这指向下一步的明确方向：学习型局部特征。
